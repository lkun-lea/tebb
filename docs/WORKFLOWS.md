## 卡片首页与画布（#230）

已确认采用 Gugu 风格的冷紫灰、圆角卡片及紧凑工具栏。首页展示实际保存的工作流，缩略图来自当前版本的节点位置和连线，显示名称、节点数、版本、触发计划和最近执行；没有保存工作流时显示空态，不把示例当作已有数据。“新建工作流”创建空白图，“从示例创建”进入独立示例选择页，“运行记录”展示最近 100 次执行并可打开原版本与节点回执。

点击卡片进入大画布；返回首页或进入计划管理保留当前画布、字段 JSON 草稿、节点位置和临时输入，“返回当前画布”继续编辑。同一当前工作流卡片直接恢复草稿；改开其他工作流或执行快照时，仅存在实际修改才确认放弃。保存仍使用 revision 冲突检查，不覆盖其他窗口更新。草稿只在本次客户端会话保留，不承诺关闭进程后恢复。

卡片开关只控制对应的现有触发计划，保留计划 ID 及绑定版本；历史版本会标明，不自动改绑当前版本。没有计划时显示手动触发；计划读取中或失败时显示具体状态，不推断为停用或手动。启用仍由原调度服务校验写入授权，失败不乐观显示成功。完整计划、原有计划及原回执通过首页“触发计划”管理；在画布的“调试与记录”配置新计划。

画布的能力栏、节点配置和调试面板可按需展开；连接表单和对齐辅助收纳在“连接与对齐”。拖拽、圆点连接、条件分支和专注画布沿用同一编辑器。概览只负责显示与导航，编辑器拥有图及执行状态，计划由共享控制器管理；UI、伙伴和调试调用继续使用同一服务。

`automation_workflow(list)` 返回定义的 `preview`（节点 ID/kind/position/label 与连线，不包含配置、发布目标或模型输入）及每个定义的 `latest_run`（无执行时为 null）。后者独立于全局 100 条历史上限，避免将较早的待核对执行显示为未运行。打开时使用 `load` 获取实际版本；不通过缩略图重建可执行图。前端隔离测试入口仍为 `node --test tests/workflow.test.cjs tests/automation.test.cjs`，覆盖卡片打开、返回保留草稿、独立创建入口、未知回执、计划绑定与发布确认；后端 `test_workflows.py` 校验图摘要投影和历史上限。

## 使用

1. 从卡片打开已有工作流，或新建、从示例创建。设计页填满工作区，“专注画布”进一步隐藏能力及配置栏，Escape返回；切换工作区页面保留草稿。从左侧点击或拖入能力，拖动节点，拖动/依次点击圆点或展开连接表单；条件选择满足/不满足。点击连线后可删除，错误连接即时提示；每份图恰有一个触发节点。
2. 点击节点填写配置。`{{节点编号.输出字段}}` 引用上游输出，右栏列出可复制字段；保存时检查节点、连线、无循环及上游引用。文本替换不执行脚本。
3. 保存后可逐步调试：每次执行一个节点，查看实际输入、输出与回执，再继续同一执行。完整运行按拓扑顺序逐个执行；条件节点的满足／不满足出口分别对应 true／false。未选分支登记为跳过，不生成输出；引用跳过节点会明确失败。
4. 发布节点分别是创建文档、写入多维表格和发送群消息。完整运行或启用定时前检查固定目标，展示内容模板并明确确认；逐步调试到写节点时单独确认已经取得的实际内容。目标和身份不能来自模型输出。
5. 失败后选择「继续原执行」，已经确认成功及分支跳过的节点不会重做。结果未知的写入须先只读核对原回执，未找到不等于未执行，不重新创建。
6. 定时触发复用现有调度，支持一次、每天和每周，北京时间，本机 tebb 须运行。定时绑定保存时的工作流版本；编辑画布不会改写旧定时。触发计划区可核对状态及启停已保存工作流计划；旧业务计划只允许停用，重新编排后按新图启用。

未编辑的空白图、示例和已保存流程可以直接切换；仅选中节点、缩放或无变化的画布通知不算修改。改名、修改配置、移动节点、调整连线或未提交的字段 JSON 才会提示放弃，取消会保留当前内容，恢复载入时的值后不再提示。新示例仍须明确保存才能执行，切换浏览不会自动创建任务或启用定时。关联修复 #224。

## 能力与边界

| 能力 | 输入 | 输出 |
| --- | --- | --- |
| 触发 | 本次触发文字，未提供时用节点文字 | text |
| 搜索 | query，最多 5 条来源 | text、urls、first_url |
| 读取网页 | 用户填写或上游提供的公开 URL | text、url、title、truncated |
| AI 处理 | prompt，可选模型条目 ID | text |
| 条件 | left、operator、right，支持等于／包含／非空 | result |
| 创建飞书文档 | title、content，可选父文件夹 token | document_id、url |
| 写多维表格 | base_token、table_id、普通文本字段、独立去重字段名 | record_id |
| 发送群消息 | 固定 chat_id、普通文本 | message_id |

网页读取复用公开地址校验与有界正文提取，不能访问登录资料、内网或执行网页脚本；truncated=true 表示仅取得节选。AI 节点复用 Atlas 传输和严格完成校验，不隐式执行工具。消息节点使用已配置且加入目标群的机器人，文档和表格使用明确连接的飞书用户；尚未连接的产品数据目录不会继承系统登录读取。

表格首版仅写已经存在的普通文本字段，去重字段必须单独存在，专门保存稳定回执编号；不会自动建表、改字段、更新用户已有记录。消息与文档会保留可见的自动化回执标记，用于断连后核对。文档正文按纯文字段落安全转义，不把模型文本当作任意 XML、附件或脚本。

首版每图最多 32 节点、64 连线，配置不超过 500 KiB；执行按现有 TaskManager 有界排队、独立工作进程，单次上限 15 分钟，模型调用上限 120 秒。停止复用进程树回收；取消、超时或退出发生在外部写入期间时，节点保留未知结果，不能将取消等同于撤销写入。

不包含循环、并行执行、子流程、插件市场或任意脚本节点。外部写入没有自动重试；网络、模型或权限异常保留失败事实。普通模型处理成功也不等于内容的语义质量已经人工验收。

## 持久化与恢复

`memory/workflows.sqlite3` 保存定义、不可变版本、执行和逐节点回执，由工作流存储单独拥有。定义编辑使用 revision 比较，冲突保留前端草稿。每轮执行保存确切版本、模式、确认过的写节点、输入及稳定请求编号；重复提交相同编号返回原执行。

写节点调用前先登记 pending；完整回执落盘后为 confirmed。任务进程结束但没有完整写回执时为 unknown，原输入和稳定回执编号保留。重新观察任务及任务入队核对不会重新发外部写入。已确认写入后的保存失败也进入未知结果，先核对后才能续跑。

Base 通过去重字段精确过滤核对，复用 CLI v3 `record_id_list` 回执解析；不使用关键词搜索的新鲜度判断。文档提供原 document_id，只读正文检查稳定标记并读取平台元数据 URL；消息提供原 message_id，核对原群和完整内容。没有可靠匹配时保留未知，不自动重放。原运行和旧版本继续保留用于审计。

## AI 调试入口

认证本地 RPC 为 `automation_workflow`，参数为 `{operation, payload}`。操作包括 catalog、list、load、validate、save、check_targets、start、get、preview_next、advance、cancel 和 reconcile。start 需要已保存的 id/version、稳定 request_id、mode（step/full）和可选 input.text；完整发布须明确 confirm_writes=true。advance 的 confirm_node 只接受当前待执行写节点。远程网页和只读协作预览不获得此 RPC。

可复制的隔离验收：

```powershell
python -m unittest discover -s tests -p test_workflows.py -v
$env:PYTHONPATH = 'E:/path/to/Atlas'
python scripts/verify_workflow.py --output E:/new/workflow-smoke
cd client
node --test tests/workflow.test.cjs
pnpm exec tsc --noEmit
pnpm build
```

verify_workflow 要求新目录，启动真实认证 WebSocket、TaskManager、独立 worker 和本机假模型，验证去重、AI 正文、条件分支、调用事件及旧作业兼容。输出 result.json 和后端日志，退出时停止隔离后端。它不会调用真实模型或向真实飞书写入。飞书契约测试使用模拟 CLI 回执，不能据此宣称真实账户的权限或发布目标已通过。

## 示例、原子能力与AI伙伴

示例均复制为新草稿，不自动保存、运行或启用定时。资讯图拆为官方来源核实→五条报告整理，复用原资讯的采集、日期和报告校验；默认最多核实8条候选，受现有预算约束，少于5条可用来源时明确失败。已确认写入包含报告来源URL的工作流回执参与跨期去重，未知写入不当作已发布；海报和原专用分阶段发布不自动搬入，文档/表格/消息需自己连接并确认。视频图为实际字幕读取→AI笔记；字幕缺失明确失败，超过节点正文范围时complete=false，不能声称理解画面或完整视频，不自动归档。

新增内置节点：video(url→text/title/url/source_id/complete)、feishu_read(固定document_id/profile→text)、news_sources(topics/lookback_days→candidates/warnings/day)、news_report(candidates/day→text/report)。外部来源仍是待核对数据，节点不会给模型新增权限。飞书连接、机器人和视频登录移到“设置→连接与网络”，引导和恢复入口指向同一区域。

为伙伴勾选“自动化工作流”（tebb可直接发现），它能调用 workflow_catalog、workflow_load、workflow_save、capability_save/load/instantiate；也可选择独立官方workflow-builder技能。伙伴生成的只是草稿。工具由父后台核对真实活动run和已授予能力，不提供模型启用定时/确认发布的旁路；任务结束后拒绝迟到写入。保存回执包含ID和版本，未知结果先读取原ID。

声明式能力用已注册kind、template和parameters定义，例如：

```json
{"operation":"<32位稳定十六进制编号>","name":"提取行动项","kind":"ai","parameters":{"text":""},"template":{"prompt":"提取行动项：{{input.text}}","model_id":""}}
```

capability_instantiate传id/version/arguments，生成普通节点及来源版本；把节点连到trigger并保存图后，实际配置冻结到图版本，之后编辑能力不会改变旧图或运行。目标群、Base、表、身份、文档和模型ID不能由参数或AI回答替换。能力不是任意代码插件，没有适配器的协议仍需产品开发。

## 本批AI调试

原automation_workflow RPC新增 templates、capability_save、capability_load、capability_instantiate，catalog同时返回内置目录和声明式能力。模型侧的workflow_authoring RPC只允许目录/读取/草稿保存/实例化，通过活动run、角色工具授权、本轮call_id及正在运行的物理task_id验证；旧阶段、取消中和已结束任务均拒绝写入，不向只读网页令牌开放。旧automation_save/manage工具同样禁止创建、启用、运行或改写工作流计划。

发布确认绑定图版本、当前运行阶段、输入和定时配置；修改后须重新确认，确认中不能切换历史。新运行预览仅使用本次输入，上轮输出不参与预览。已有定时可载入其固定版本继续编辑，保留原ID、名称和启用状态；逐步继续同时核对expected_attempt，防止旧确认推进新阶段。

UI、伙伴和其他模块复用同一WorkflowService及业务适配器。AI保存按原工具调用编号幂等，更新需revision，旧版本可读；同一持久产物版本只记一次真实预算进展，不因新工具名字被误判无进展，也不扩大预算。

```powershell
python -m unittest discover -s tests -p test_workflow_authoring.py -v
python scripts/eval_agent.py --case workflow_authoring --limit 1 --samples 1 --timeout 120 --output <新的隔离目录>
# 真实模型仅在已隔离配置且明确授权时加 --live；本用例最多8次模型调用，只保存本机草稿，不向飞书写入。
```

评测必须核对落盘能力、图引用、来源版本、布局、未发生工作流执行和认证父服务退出；不是HTTP成功或口头声称搭好。全部失败和超时保留。实际完成及未验证项记录于各关联issue。

## 示例的真实场景验收（#227）

`scripts/verify_workflow_scenarios.py` 沿用认证RPC→工作流服务→任务进程→原节点适配器，明确加`--live`才运行。先准备仅含选定模型连接、网络与容量设置的隔离bootstrap，不复制聊天、工作区、视频来源缓存或原有定时。每个输出目录必须全新，保留来源代码摘要、图/运行/任务编号、节点回执、实际模型调用与失败；退出核对服务/工作进程并删除临时凭据。

```powershell
$env:DESK_COMPANION_DATA_DIR='<仅含选定连接的隔离bootstrap>'
python scripts/verify_workflow_scenarios.py --live --case tech-news --case video-notes --video-url 'https://www.youtube.com/watch?v=eIho2S0ZahI' --timeout 600 --output '<新结果目录>'
```

默认资讯图最多2次模型调用（一次生成、一次契约修正），视频图一次；不增加工作流或模型的既有执行预算，不为成功而注入候选或放宽校验。资讯须返回5条唯一来源且ID/URL绑定实际采集结果；视频须取得实际字幕、生成含时间点的笔记并说明部分覆盖。语义质量仍须对照来源审阅，这些检查不等于形式化事实证明。

飞书用例为`feishu-document`、`feishu-base`、`feishu-message`。须先明确专用测试目标，私有`--write-targets` JSON只含profile及parent_token/chat_id/base_token/table_id/key_field/content_field，未提供的目标不会猜测。再显式加`--confirm-test-writes`，才会创建标题“tebb 工作流验收 2026-11-02”的文档或写入/发送“这是一条 tebb 工作流验收数据，不含业务内容。”。写后复用原reconcile只读核对远端回执及正文，未知结果不重发。未授权项记录pending，不能算通过；`--use-connected-video-login`仅按需复制产品内的DPAPI加密登录副本并在退出删除，不读取外部浏览器。

群消息核对使用当前CLI的`im +messages-mget --message-ids <原消息ID> --no-reactions --format json`，要求返回唯一、未删除的文本消息，且原消息ID、群ID和完整正文（含稳定回执）均匹配。核对不调用发送命令。多维表格验收还会按原record_id投影读取内容与去重字段，显式传`--format json`，逐项比较实际单元格，不能只凭返回记录ID判断任务完成。

2026-11-02实际结果：固定TED公开视频图一次真实模型调用完成，取得完整平台字幕、时间点笔记及覆盖说明；核心框架和时间点对照字幕吻合，但个别英文术语及原文外解释存在质量遗留，执行通过不等于内容逐句准确。首次资讯图取得来源但两次返回每条5个key_points，违反2–4条约束而失败。已补齐系统提示与带条目编号/实际数量的修正反馈，保留原严格校验；修正后的新一轮默认图完成5条报告及实际来源绑定核对。两轮原始结果、失败和清理证据全部保留，没有以第二轮覆盖第一轮。

用户随后确认云盘文档、指定测试群，并允许新建专用Base；原工作流分别创建1篇文档、写入1条记录、发送1条机器人消息，正文均为已确认验收文字。文档正文、表格实际单元格/回执及群消息ID/目标/正文只读核对通过，未调用模型。首次群消息自动核对因调用未注册的CLI命令失败，修正到上述shortcut后只核对原消息，未再发送。初始失败、后续只读核对及临时配置清理分别保留。浏览器/原生人工点击与组件回归分开报告。
