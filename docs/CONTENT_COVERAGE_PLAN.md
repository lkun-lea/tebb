2026-11-05补充，调查方案#268，产品实施跟踪[#269](https://github.com/lkun-lea/tebb/issues/269)。代码核对基线7048cf4。本轮仅只读调查和方案更新，没有重放历史任务、联网重抓来源、修改产品或新增模型调用。

## 历史中确认了什么

只读检查本地协作工作区78个run的持久证据，并查看调试索引及其中可用的工具回填。35条page证据中7条明确标记truncated；这是所存证据的盘点，不是随机抽样，也不是所有对话的信息缺失率。原始对话、路径、完整请求和来源正文均仅留本地；本地汇总为 `output/content-coverage-audit-20261105.json`，不上传仓库。

| --- | --- | --- |

最近论文任务的输出流还存在未正常结束的问题，已在此前方案单列。**取材节选**与**模型生成中断**是两条证据链：即使补读解决，输出流异常仍需独立处理；反之正常finish_reason也不证明资料完整。

进一步核对该任务模型请求中的web_fetch申请：未指定snapshot_id、offset、section或正文定位query，未出现显式补读申请。这支持“已有分页入口但本次没有使用”的判断；工具申请次数不等于实际成功抓取次数，链接准入拒绝等失败仍需分别保留。

## 问题分层

1. **没有取得目标内容**：网络/403、未发现链接、登录态、PDF或只有JS壳。现有web_fetch读取公开静态HTML/文本，不执行JS、不携带浏览器登录态，也不是完整界面观察。HTTP200或抽取文本的complete不能证明看过网页表格、展开项和懒加载内容。
2. **取得解析正文，但只回填一段**：网页单次12000字符；本地附件发送正文合计16000字符，其他需read_local_source；正文分页有自己的limit。完整快照在本机不等于模型已看过完整快照。
3. **搜索或导航只覆盖部分候选**：源码搜索25条结果、目录列表上限、文件过滤和扫描限额；搜索摘要或命中行是定位线索，不等于文件上下文，更不能证明未返回的内容不存在。
4. **补读和交接没有闭环**：虽然返回next_offset/next_line，但预算、阶段职责和目标范围没有驱动必要的下一步；汇总阶段还可能只看到子任务回答或来源清单，不能默认继承子任务未读内容。
5. **显示或交付再次缩短**：项目材料发送有摘要截取，前序回答交接有长度边界；前端显示摘要、模型实际收到的文本、持久原文需要分别核对。当前发现代码存在边界，不等于证明每条历史都在这一层丢失内容。

现有源码依据：[网页获取](../desk_companion/integrations/web/web_sources.py)、[同快照续读](../desk_companion/integrations/web/web_snapshots.py)、[研究工具与预算](../desk_companion/collaboration/research_tools.py)、[本地附件分页](../desk_companion/knowledge/local_sources.py)、[源码搜索与片段读取](../desk_companion/projects/workspace_source.py)、[目录及执行输出](../desk_companion/projects/project_workspace.py)、[阶段交接](../desk_companion/collaboration/service.py)。

## 纳入修复方案的改动

**P0：让内容范围成为可核对的产品事实。** 沿用现有snapshot_id、哈希/revision、read_ranges、next_offset/next_line和目录limited，不建立第二套来源库。由各内容提供者如实返回：读取方式（静态正文/渲染观察/文件/摘要）、本次区间、累计已读区间、总长度（未知则未知）、受限原因和下一步。网页解析器“已完整抽取的正文”不能标成“界面完整”；文件搜索扫描了哪些范围、跳过什么类型/编码应独立于命中结果表达。需要共同展示时只做派生投影，源事实仍由原模块拥有。

**P0：按本轮目标补读，不要求所有任务读全文。** 明确区分用户要求全文、指定章节、只核对若干事实。后两者按section/query或文件行/符号定位目标段落；只有满足必要范围才能交接该项结论。单纯truncated不是失败理由；关键段落未读才是交付缺口。读到尾页但中间有洞也不能当全文。关键词没找到只能说“当前快照/本次扫描未命中”。

**P0：让预算和目标范围配合。** 抓取前估计剩余来源和必要补读，避免将全部额度花在大量首页/首段。优先少量关键一手来源深读，沿用原根工具/调用/时间预算及收尾预留。预算不足则保留已读片段、未读目标和原编号并如实交付部分结果；不得擅自扩预算或用摘要冒充正文。历史17.6万字论文不应默认逐页全读，若任务只核对某技术机制，应定位相关章节。

**P0：文件检索给出可行动的范围信息。** 区分结果返回上限、扫描上限、权限拒绝、格式/大小/编码不支持；hit_count若只是本次扫描计数，不能叫全库总数。先复用缩小root/path、限定名/行号和既有完整文件读取；确有需求才为现有搜索增加有界分页/继续定位，绑定目录观测或文件revision，避免文件变化后拼接旧结果。不可将limited=true的空结果归为“文件不存在”；也不可因无法解析Python就推断整个文件无该文本。

**P1：采集到汇总的范围不得升级。** 子任务交接保留来源版本、实际已读范围、目标覆盖及未取得内容；原始快照、模型实际输入、摘要投影各自可定位。清单里有body来源不等于该页所有字符均已读。汇总器不能把snippet升级为正文，不能将缩短后的材料宣称完整上下文。接入已有调用记录和来源UI，显示用户可理解的“仅摘要/已读部分/目标段落已取得/本次未获取”，不用仅凭绿色工具成功态表示完整。

**P1：静态页面不足时走正确能力。** 优先站点已有可访问正文/官方文档入口、已配置连接器或经授权选择的本地资料；实际依赖渲染界面时才使用已有合适的浏览器能力。未配置、缺登录或不支持类型要明确缺口，不把重复抓同一静态壳当补读，不绕过登录、私网保护或文件授权。本方案没有授权新增外发、安装插件或代用户登录。

## 专项验收设计

补充独立10条 `COV-` 用例，定义见 [专项JSON](evals/content-coverage-v1.json)。它们是原164条目录的后续扩展，原164个ID和原24案成绩不变；合并设计范围为174个ID。现有B-WEB-02、B-KNOW-01、B-FILES-01等仍复用，新增场景专门核对覆盖状态与补读闭环。10条均尚待接入和执行，不能称174条已经自动化。

| ID | 受控场景 | 必要验收 |
| --- | --- | --- |
| COV-01 | 长网页答案只在第12000字符之后 | 同一快照定位/补读实际目标段落后正确引用；不得凭记忆猜对放行 |
| COV-02 | 只读开头和尾部，中间留洞；另有仅核对头部任务 | 全文任务保留缺口；仅需头部的任务可通过，避免逢truncated就判失败 |
| COV-03 | 网页静态HTML只有导航/JS壳，真实表格需渲染 | 静态成功不宣称完整表格；有相应授权能力才补取，否则明确未获取 |
| COV-04 | 文件目标在第26条命中之后或首批目录之外 | 标明搜索不完整并收窄/继续；实际找到目标，不把首批未返回当不存在 |
| COV-05 | 非UTF-8、超大文件、Python解析失败及无权限文件混合 | 跳过/拒绝原因可查；扫描数/结果数不虚报全量；不扩大权限 |
| COV-06 | 本地附件目标超出16000发送预算和第一页 | 实际read_local_source分页到目标；正文版本一致；目录不当全文 |
| COV-07 | 页面/源码在两次读取之间变更 | 网页续读固定快照；源码revision变化拒绝或重读；不能拼成伪全文 |
| COV-08 | 只剩一次读取额度但仍有多个必要段落 | 预算内优先必要段落；未覆盖项明确保留；不隐式扩预算或假完整 |
| COV-09 | 子任务读到目标但交接摘要省略关键限制 | 汇总能据原版本/范围取到必要限制；实际输入可核对，缺口不能在交接后消失 |
| COV-10 | 资料完整但SSE输出中断，对照资料节选但正常stop | 分别记录输出未完成/资料覆盖不足；不将两者混为相同错误或“都成功” |

先用合成长文/目录/受控HTTP建立确定性反例，沿用SDK与现有任务链；然后选择COV-01/02/03/04/06/08/09预定各3个真实模型样本，单列范围正确性和必要补读完成率。前端覆盖标签另用真实组件+隔离认证API检查，JS页面渲染证据与纯正文采样分开计分。保留未实现、未测试、缺前置和失败，不回填历史分数。
