## 执行分层与独立判定

1. **确定性服务和故障注入**：用临时目录、受控时钟/适配器、真实SDK及MockTransport验证状态、授权、幂等、版本、预算和收尾。来源不能来自模型自述。EOF、缺结束帧、未知副作用必须在本地可重复复现，不等真实供应商偶然失败。
2. **真实模型**：复用 `scripts/eval_agent.py` 和现有产品任务链；新增业务题只补领域prepare/verify适配器，不另起旁路Agent。核对实际输入、工具回执、产物和最终状态，不能以HTTP200、非空回答或裁判模型一句“通过”替代。
3. **真实产品界面**：用当前组件连接隔离的认证本地API，验证打开/编辑/取消/保存、焦点与窄屏。组件行为测试、浏览器操作、Windows桌面/安装虚拟机分别记录。模型生成日程提案不等于实际打开过表单。
4. **真实外部集成**：仅测试租户、专用身份和白名单目标。默认适配器不外发；真实只读与真实写入各有独立开关、前置和回执。用户当前授权的业务测试不自动变成向个人飞书群发送消息的授权。

一条案例可包含多个层级标签，只有其必要层都完成才能宣称整条通过。例如J-03模型和服务通过、UI未测时必须保留UI缺口；不能在总体里算完整通过。目录当前有84条带模型标签、127条带服务标签、73条带UI标签、10条带沙箱标签、24条带故障标签、2条带真实外部标签；标签数量不能相加作为案例数。路径权限、CAS、认证等可确定验证的用例不因同域存在模型题就额外要求付费调用。

结果使用 `pass / fail / unverified / blocked_prerequisite / not_implemented / not_run`。产品的failed、needs_input、cancelled或unknown是被观察的业务状态，不能直接映射评测成败：反例按预期拒绝、待核验或取消且无禁止副作用才通过。缺少适配器、没有模型余额、没有测试租户、没有沙箱都明确进入对应缺口，不能算通过或悄悄移出计划分母。

**建议准入标准**：必要确定性断言全部通过；越权、伪造完成、重复副作用等P0反例零误放行；P0模型题预定3样本全部保留，未达3/3则该题不通过本次准入；P1分别报告通过/失败/待核验，不能用高分抵消P0缺陷。3样本仍不证明统计稳定性。首批164项尚有117项未接入，当前不能声称达到这套准入标准。

## 运行组合与成本边界

- **变更回归**：按受影响领域运行现有服务/组件测试和对应业务案例；共享任务/引用/权限变化同时纳入跨域旅程。测试文件映射在领域 `coverage_anchors`，只证明存在复用入口，实际范围须读具体断言后选定。
- **冒烟**：目录 `suites.smoke` 固定24条，检查核心读写、补充、日程表单、工作流确认和故障边界。它与历史24条失败集是不同集合，不混分；这份冒烟目前也需要适配器，不能直接交给现行CLI执行。
- **完整业务回归**：164条逐项记录所有必要层，含8条旅程；沙箱/真实外部层缺前置时报告blocked，保留分母。不能只跑能跑的47条后称完整回归通过。
- **真实模型采样**：先接入并验证相关适配器，再冻结模型ID/配置、源码和测试数据。建议模型题每题3次；84条全部执行即252个样本，实际调用数通常更多，尚无可靠总费用估计。先用预定小批采样观测成本，决定完整批次预算后冻结，不在跑完后挑题或挑样本。
- **已知失败复测**：先做下述方案的确定性反例，再对恢复、legacy并行、Atlas并行、日程提案各3样本独立实测。若输入/验收改变则属于新契约，原24案继续单列；不将旧失败改判或重试结果替换原样本。

每批记录任务样本数与实际调用数、已回报usage及完整性、费用未知、各阶段耗时、首字节/结束信号、HTTP/供应商错误、task/root/call/operation/source/version关联、清理事实。采集期间固定源码；模型输出协议错误、供应商错误、工具错误、任务生命周期错误、独立验收错误分别归因。沿用产品预算和取消契约，本设计不新增按总耗时杀进程的通用规则。

## 复用入口与接入顺序

现有命令无需新增执行器即可复跑原任务质量案例：

```powershell
# 仓库根，先准备当前依赖、固定Atlas及skills；使用新的输出目录
python scripts/eval_agent.py --suite failures --limit 24 --samples 1 --output ../output/failure-fixture-new
# 已授权真实模型、显式固定RFC归档目录；以下会产生模型费用
python scripts/eval_agent.py --live --suite failures --limit 24 --samples 1 --research-corpus ../output/research-171-corpus-real --output ../output/failure-live-new
```

这些命令只运行现有失败24案，不是新164项完整业务回归。`business-regression-v1.json` 是设计清单，当前CLI没有 `--suite business`，不得把文档命令写成已存在的功能。现有47项按 `Q-` 的 `automation.eval_case_id` 对应现行 `--case`；README中的项目和资料准备条件仍适用，沙箱题须显式启用。

推荐接入顺序：先修复#258/#259/#260并补其正反用例；其次为同根恢复、提案表单和引用渲染等P0补业务适配器；再连接资料/记忆/工作流/事项真实持久链；最后纳入沙箱、安装和独立测试租户。每项适配器实施需独立issue及验收，不将本设计提交当成实现完成。

现有冻结批次保持：原12题首轮5通过/2失败/5超时，v27为9/3/0；v27完整24题20通过/4失败/0超时。新164题没有总体实测分数。
