# 角色视觉复审与 Live2D 重设计提案

2026-11-05。调研记录 [#276](https://github.com/lkun-lea/tebb/issues/276)，角色实施与视觉验收 [#272](https://github.com/lkun-lea/tebb/issues/272) 重新打开。

状态：**原有三角色动画未通过用户视觉验收；本文是待评审的新方案，不代表已完成原创 Live2D 模型或已迁移客户端。** 画像地图、角色库和多形象选择需求继续保留。当前客户端代码本轮不变，旧原稿与实现记录保留为被替代方案。

## 本次失败与修正原则

用户指出关节一眼可见断开，手部方向与原画、人体动作不一致。初版以生成的独立部件做位置配准，再通过 DOM 旋转播放；它没有完成统一原画的运动补绘、连续轮廓与自然手势校形。增加插值只能让错误姿态之间的运动更连续，不能修正美术与人体结构。

之前的 296 项前端回归验证了功能、隔离、状态与生命周期，不证明角色好看、手型自然或关节连续。本次将“技术验证通过”和“用户视觉验收通过”分开记录；旧角色不再视为最终采用版本。

手部按完整姿势设计：掌心/手背、拇指所在侧、腕部连接、肘部弯曲和衣袖遮挡保持一致。挥手展示掌心可以是自然动作，问题在于具体姿态是否连贯；不以“所有掌心一律朝外”或“一律禁止露掌心”作为机械规则。

## 已核实的项目基础

- `client/src/pet-render.ts` 已使用 PIXI、`pixi-live2d-display/cubism4` 与 Cubism Core 加载模型，支持透明画布、动作组及优先级。
- 现有凯尔希运行目录有模型、纹理、物理与动作文件；动作组为 Idle/Busy/Fail/Talk/Done/Tap/Wish，未注册独立的挥手和指向动作组。
- 已检查的模型目录未发现 PSD 或 `.cmo3` 编辑源，不能声称知道作者完整的拆件与绑定方式，不能用运行模型替代原创角色工程。
- 当前桌宠渲染器使用模块级单实例，第二次启动会销毁第一个；画像页需要独立实例的加载、切换隔离、缩放、隐藏暂停和销毁边界。宜保持“一个活动模型＋静态形象缩略图”，复用已有加载与播放能力。
- 本机有现成模型与 Core 的播放基础；已检查位置未发现 Cubism Editor，不能排除其他位置存在便携版。三种原创角色目前均没有可编辑绑定工程和导出的 Live2D 模型。

本轮只读核查本地模型元数据，不复制凯尔希模型、纹理或 Core 到设计归档或公开仓库。

## 推荐制作路线

**完整原画 → 拆件与遮挡补绘 → Cubism 网格/变形器建模 → 动作与手型校形 → 真实模型播放评审 → 客户端接入。**

1. **先审完整原画。** 统一人物比例、服装与肩颈关系，分别画自然垂手、屈肘示意、小幅侧向挥手。先确认角色完整状态下成立，再拆件。
2. **拆件并补全运动后会露出的区域。** 肩部、袖口、肘部、腕部、颈部和头发交叠区域需要补绘与明确遮挡；保留可编辑的原始分层 PSD 和导入 PSD。
3. **在 Cubism 中建模。** 为原画建立 ArtMesh，结合 Warp/Rotation Deformer、参数关键形与必要连接约束，逐个检查运动后的轮廓。Live2D 也使用分层素材，质量来自原画准备与绑定校形，换播放器不会自动修正错误关节。
4. **单独设计手型组。** 放松手、侧面示意、挥手分别确认掌背和拇指方向。需要改变手型/手臂形状时，使用预先绘制的替换部件与姿态切换，在合适时机过渡，避免用同一张手掌图覆盖所有角度。
5. **制作并导出真实运行资产。** 保存 `.cmo3` 工程，导出兼容的 `.moc3`、模型设置、纹理、动作及物理数据。先在 Viewer 和目标 WebView 检查一段含抬手、手势和收手的动作，再接入产品。

对应官方依据：[制作流程](https://docs.live2d.com/en/cubism-editor-manual/workflow/)、[素材拆分](https://docs.live2d.com/en/cubism-editor-manual/divide-the-material/)、[变形器](https://docs.live2d.com/en/cubism-editor-manual/deformer/)、[手臂形状与部件切换](https://docs.live2d.com/en/cubism-editor-manual/animation-preparation/)、[导出运行文件](https://docs.live2d.com/en/cubism-editor-manual/export-moc3-motion3-files/)。

## 待评审的美术方向

三类可选形象继续保留，重新制定统一的原画和动作标准：

| 类型 | 新原画方向 | 动作重点 |
| --- | --- | --- |
| 人物，作为首个正式样件的推荐方向 | 原创精致半身插画，正常肩颈和手臂结构，服装自然覆盖连接区；透明背景，降低厚重描边 | 呼吸、眨眼、轻点头、屈肘示意、小幅侧向挥手 |
| 机器人 | 完整外壳和有设计依据的关节罩，连接结构属于整体原画 | 屏幕表情、轻摆动、符合机械结构的示意动作 |
| 小动物 | 统一躯干与毛发/服装连续性，四肢与爪部遵循该动物的造型语言 | 耳朵、表情、身体重心及小幅爪部示意 |

这是对既有三类选择的重设计提案，用户尚未批准新原画。先同时评审新的完整原画与手势设定；一个真实 Live2D 样件通过后，再将确认的制作标准扩展到全部角色。角色数量保留，避免在美术标准未确定时重复制作三套不合格模型。

## 评审与验收顺序

- **原画评审**：完整角色、不同背景上的轮廓、三种自然手势，按实际显示尺寸及放大尺寸检查。此时不修改客户端。
- **模型样件评审**：提供真实 Viewer 或模型运行录屏，包含待机→抬手→手势→收手→待机；检查极端角度、左右手、掌背、袖口、肩肘腕与头颈接缝。PNG 模型图或程序测试结果不替代本项。
- **目标环境评审**：在实际 WebView 验证停留和动作中切换、隐藏/恢复、连续触发、缩放、暂停及模型销毁，记录实际帧时间和异常；不以导出文件标注 FPS 代替实测。
- **扩展与接入**：样件通过后批量制作、核对三角色切换与界面配合，再替换当前未通过方案。原画、PSD、绑定工程、导出资产和录屏按来源与授权归档。

正式模型需要可编辑原画、补绘与 Cubism 绑定制作，不能承诺把现有 PNG 部件自动转换为合格 Live2D。发布接入前另核对与现有 SDK 的导出兼容性及 [Cubism SDK 发布授权](https://www.live2d.com/en/sdk/license/)，本提案不作费用或授权结论。
