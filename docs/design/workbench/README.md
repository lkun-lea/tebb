## 产品目标与协作边界

tebb 给不同岗位的人和 Agent 提供推进项目所需的工具。正式需求群中，产品、研发、测试和质量负责人的个人 Agent 按岗位分工执行与交接，人负责各自的决策，项目负责人跨需求统筹交付。同一人可兼任角色。每个云账号对应一个个人 Agent，群内可以协作多个成员的 Agent；同一个 Agent 在不同项目中的能力由实际岗位与授权决定。普通聊天用于日常沟通，正式需求群由人立项创建，群内同时呈现讨论、阶段与证据。绑定、授权和账号交互详见[账号与登录设计](ACCOUNT_DESIGN.md)。

| 角色 | 专业能力与交付 |
| --- | --- |
| 产品 | 根据调研来源澄清范围、异常和边界，可使用 `grill-me` 或 `grill-with-docs`；产品负责人确认版本与必过条件。 |
| 研发 | 通过项目「规格」入口使用 OpenSpec，维护仓库中的提案、设计、行为规格与任务；交付候选及自测。研发跟进 CI、失败修复和候选包。 |
| 测试 | 依据已确认规格形成固定验收计划，覆盖正常路径、边界、失败恢复和权限；AI 行为另维护可重复运行的评测集，记录数据、预期和实际证据。 |
| 质量负责人 | 中途核对偏离与证据缺口，交付前逐条核对当前版本。试点比较有无中途监督的返工轮次、等待、耗时和有效发现；两组使用同一独立验收。正式发布由获授权的负责人执行，可由研发兼任。 |
| 项目统筹 | 项目负责人或被授权的项目管理部门成员维护里程碑与依赖，协调负责人、时间与阻塞，跟进直到解决。产品负责需求和取舍，测试负责实际结果，质量负责人负责交付复核。 |

岗位 Skill 由 [tebb-skills](https://github.com/lkun-lea/tebb-skills) 管理。平台开发者维护资料检索、仓库、沙箱、测试等工具模块及其权限、版本和回退。项目资料与工具使用项目授权，岗位交接使用需求状态与证据。

## 页面结构与交互

| 页面 | 默认呈现 | 操作与跳转 |
| --- | --- | --- |
| 工作台 | 保留聊天、项目、日程、事项、工作台的全局入口。工作台主体是「常用工具」与「工具目录」，分类为通用、产品、研发、测试与质量、项目管理。每张卡显示名称、图标和用途，窄窗口卡片自动换行。 | 展示当前成员可发现的工具；用户可把有权限的工具加入常用，岗位分类用于浏览。点击卡片直达工具原页面，项目级工具携带当前项目或先选授权项目，再打开目标工具。 |
| 工作台 → 项目统筹 | 默认列出所有获统筹权限的项目，可筛选单个项目。显示里程碑目标日期、风险、前置依赖、阻塞和下一位跟进人。 | 从阻塞定位原需求群和阶段。授权负责人可登记跟进、协调负责人或时间、发起提醒和升级，处理记录回写到对应需求和项目时间线。 |
| 日程与事项 | 日程和事项分别通过原全局入口打开；项目列表展示当前账号有权访问的所有项目。 | 日程沿用现有周视图、单日/月份视图及已有拖拽、改期和同步规则。事项安排继续复用原有表单。里程碑日期由项目计划维护，会议或协作时间可由用户通过现有日程显式安排。 |
| 项目 → 时间线 | 进入项目默认打开时间线。按本地日期倒序聚合该项目内的需求立项、决策、阶段交接、阻塞、返工、验收和构建发布事件。右侧可直接打开进行中的需求。 | 时间线用事件的持久时间与序号排序。点击需求事件定位到对应阶段，点击进行中的需求定位到当前阶段，构建事件打开该构建。返回恢复时间线的滚动位置。新事件可补读，断线重连时按事件标识去重。 |
| 项目 → 需求 → 流程 | 需求版本和当前阶段置顶。流程横向显示「需求确认 → 实现与自测 → 独立验收 → 质量复核」，窄窗口换行。需求详情可打开同一需求群的聊天。 | 每个节点显示实际状态和负责人，当前运行阶段与浏览选中的节点各有标识。点击历史节点可检查当时的交接；查看历史不会触发操作。群内的流程入口与项目页打开同一份状态和证据。 |
| 项目 → Issues | 与时间线、需求、规格同级。默认展示项目绑定仓库有权查看的开放与已关闭 GitHub Issue。 | 按状态筛选，按标题或编号搜索；打开卡片可查看详情与关闭原因，并去 GitHub 原文进行修改。 |
| 阶段详情 | 负责人、待处理动作、阻塞原因和关联版本置顶。下方切换「摘要」「文档」「产物」「验收证据」。 | 文档打开固定版本原件；产物打开候选、差异、构建或报告；证据可逐条展开。摘要显示本阶段的输入、输出、交接和下一步。空态说明缺什么，权限不足与加载失败分别提示；保留可读历史并提供重试。 |
| 项目 → 规格 | 当前项目已授权仓库中的 OpenSpec 活动变更与归档。 | 项目内独立打开；需求详情可直达关联变更。按仓库、分支、变更和版本打开提案、设计、规格、任务与校验回执。 |

### 工具接入与授权

- 工具通过版本化登记描述稳定标识、名称、图标、分类、入口、账号或项目作用域、所需权限、可用状态与版本。客户端根据登记渲染卡片和定位入口。增加、下线或回退一个工具通过修改对应登记及模块完成。
- 「常用工具」按成员保存稳定工具标识。撤权后重新检查可发现范围与访问权限；旧收藏或直达链接都要重新鉴权。成员兼任多个岗位时按实际授权展示能力，同一工具只出现一次。已授权但暂不可用的工具显示原因。
- 界面入口和 Pi 可调用的工具分别声明能力。Agent 只在现有运行授权内调用已注册能力；用户点击、加入常用或打开岗位分类不会授予任何工具权限。OpenSpec 卡片定位项目内独立的「规格」页面，活动变更以项目仓库为准。

## 项目统筹如何介入

企业可将统筹权授予项目管理部门的指定成员，按项目组合分配查看和协调权限；项目负责人可在单项目内兼任。小团队可由现有负责人兼任。需求阶段仍由对应职责和证据推进，统筹介入适用于计划偏离、依赖冲突、无人接手、逾期与需要跨部门决定的情况。

1. **定计划。** 立项时确定目标日期、交付里程碑、负责人及前置依赖。统筹人员维护计划，记录调整人、原因和前后日期；需求完成度和验收结果来自实际阶段与证据。
2. **看风险。** 根据实际阶段事件、依赖状态、计划日期和责任人识别阻塞。统筹页可定位到产生风险的里程碑、需求、阶段和原始证据；跨项目依赖的内容按访问权限显示。
3. **协调推进。** 选择阻塞后登记责任人、待处理动作和期望回应时间。相关人收到带需求与阶段链接的站内提醒。同一跟进操作重试复用原记录；超过约定时间可升级给有权限的项目负责人或部门负责人。人可在授权内调整计划、协调资源或提交改派，执行中的阶段继续走原有交接与执行权校验。
4. **解决与回顾。** 责任人更新结果或补充证据，原阶段负责人按条件继续；协调记录保留在需求群和项目时间线。统筹 Agent 可基于已授权事实归纳风险、建议下一步和起草提醒，正式改派、改期与升级由获授权的人确认。统筹权限仅含获授予的计划与协调操作；需求范围、验收判定、质量放行和发布分别核验对应岗位权限。

例如桌面候选依赖弱网验收，测试报告缺少可复跑环境。项目负责人从阻塞定位测试阶段，跟进研发提供环境和预计时间；环境就绪后测试在同一候选上继续跑，质量负责人依据新证据判断能否交付。协调时间、阻塞原因和处理结果可按原记录追踪。

### 统筹页交互

| 界面 | 显示与操作 |
| --- | --- |
| 里程碑总览 | 默认查看全部获统筹权限的项目，按目标日期排列，可筛单个项目。显示依赖方向、风险原因及受影响的下游里程碑；点击有风险的里程碑或「待协调阻塞」进入同一阻塞。 |
| 阻塞详情 | 显示关联需求和阶段、阶段负责人、依赖、影响和处理记录。点击「提醒责任人」先核对接收人、待处理动作与回应时间，再明确发送。提醒带原阶段链接，状态变为「等待回应」。 |
| 逾期与升级 | 到期时仍缺约定回应，显示「回应逾期」并开放「升级跟进」。确认页列出原截止时间、获授权的升级接收人、原责任人和升级原因；确认后保留跟进历史及原任务归属。已发出的操作按编号核对并去重。 |
| 解除与恢复 | 回执到达后显示「待阶段负责人确认」。阶段负责人从原阶段打开回执，核对其适用的候选和验证计划后确认解除，再由该成员的 Agent 在原阶段继续。原候选仍适用时继续原候选，否则按既有证据失效规则重验。返回总览时可见环境就绪和下游实际阶段状态。 |

## GitHub Issues 看板

- 项目「Issues」子页面读取项目绑定且账号有权查看的 GitHub 仓库。以 GitHub 仓库 Issue 为基础集合，逐页加载开放和关闭的记录，过滤 Pull Request、去重，多仓按仓库标识和编号区分。分页未完成时明确显示已加载范围，空库、无授权和读取失败各有状态。
- 默认显示全部，可切换开放、已关闭，支持标题与编号搜索。配置了可读的 GitHub Projects 时，可按该项目的状态列显示开放 Issue；未加入或未填写状态的开放 Issue 进入「未分组」。关闭项进「已关闭」，有关闭原因则展示原原因。没有 Projects 配置或授权时按 Issue 状态显示开放与已关闭，并说明数据来源。Projects 字段与 Issue 状态在详情分开呈现。
- 卡片含仓库、编号、标题、标签、负责人，关闭项展示关闭原因。点开详情可以查看原始链接；关闭详情后保留当前筛选与列表位置。首版在 tebb 只读，创建、编辑、分配、变更状态及关闭通过 GitHub 原文完成。
- 刷新重读 GitHub，显示成功读取时间。限流或网络故障可显示同一授权范围的上次成功快照并标记过期。切换项目、撤权或连接断开后重新核验访问权限，清除不再获准的卡片、详情与搜索结果。私有仓库权限来源见[账号与登录设计](ACCOUNT_DESIGN.md)。

## 流转与交接

有权限的人确认立项并创建需求群。项目、原事项和群采用稳定关联；重复请求返回同一个群。候选调研可在立项前由 Agent 协助。阶段推进以业务服务确认的事件为准，聊天文字与模型结论可以作为待核对信息挂入需求。

| 当前阶段 | 可推进的条件 | 失败与返回 |
| --- | --- | --- |
| 需求确认 | 产品冻结需求版本、验收条件和分工；研发接手时可核对规格绑定和权限。 | 缺信息则等待对应负责人，保留待决策项和来源。 |
| 实现与自测 | 研发提交固定候选、关联 OpenSpec 版本、改动范围、自测结果和未完成项；实际回执入档后交给测试。 | 实现失败保留错误和可恢复步骤；缺业务决策回到产品确认。 |
| 独立验收 | 测试按固定用例和预期验证同版候选，逐项登记真实结果；必过项均有效才进入质量复核。 | 用例失败带复现步骤、预期、实际和原始证据退回研发；需求不清进入等待产品决策。 |
| 质量复核 | 质量负责人核对当前版本的必过条件、证据及风险，明确确认交付；发布操作按发布授权另行触发。 | 证据不足退回测试补验，代码问题退回研发，业务问题转产品。中途发现同类问题可提出带依据的阻塞或返工。 |

阶段支持待开始、进行中、等待决策、阻塞或失败、暂停、返工、已完成和取消。退回需要目标阶段、原因与证据或缺口，旧尝试继续可查。负责人接手或交还时，保存当前版本、候选、未完成项、有效证据和恢复位置。同一阶段的当前执行权由服务端校验，迟到或被接手的旧执行者不能覆盖最新结果。一次业务交接只生成一次通知，通知带下一位负责人、动作、依据和详情链接。收到重复请求或事件后查回原结果。

需求、候选、验证计划和执行环境的版本与证据一起留存。影响范围可证实时重验受影响项，影响未知时重新验证相关必过项。界面将旧结果显示为历史或已失效，当前完成度只统计当前版本有效证据。阶段详情展示验收编号、用例与预期、实际结果、执行人或运行编号、时间、环境、候选版本及原始回执。命令证据包含实际命令、退出码和输出，适用时附截图或产物。当前必过项逐条显示通过、失败、待核对或已失效。

## Agent 按需读取上下文

1. 开始阶段工作时直接提供当前已确认需求与版本、验收条件和阶段职责。首次接手也提供必要的交接指针与已知待决策项。独立验收阶段通过指针取得固定候选与验收计划。项目说明作为索引，指向仓库、开发规则、验证环境与项目资料。
2. 阶段 Agent 或成员的个人 Agent 可以按问题检索已获准的项目资料、需求群原始记录、决策、历史版本和验证证据。先返回来源目录或相关片段，按需打开指定章节、消息或日志区间。读取按现有运行预算限制条数与长度，长文分页补读；摘要和引用保留原文位置、资料版本及来源类型。个人会话内容由本人选择共享回群。
3. tebb 在检索、打开、续跑和引用解析时校验账号、项目、群与原件权限；权限收回后清理运行可再用的相关上下文，受限的来源标题和摘要也不返回。资料冲突时展示当前确认版本及冲突出处；关键条件缺失时挂起依赖它的步骤并向负责人提出具体问题。新人可用同样入口查相关模块、业务约束与既有用例，并打开原文。
4. 界面显示「当前阶段带入」和「按需读取的资料」，运行详情可按运行编号核对实际采用的来源、版本和读取结果。Pi SDK 执行模型与工具循环，tebb 的业务服务持有阶段、权限、交接和证据。时间线、工作台和需求群读取同一业务记录；事项、日程和仓库仍由各自服务维护。

## 实施依赖与验收

本机阶段复用项目、日程、事项、规格及阶段记录，打通工具目录、项目内定位和单项目统筹。Pi 接入依赖 [#293](https://github.com/lkun-lea/tebb/issues/293)；项目部门的跨项目授权、跨账号接力及站内提醒依赖 [#312](https://github.com/lkun-lea/tebb/issues/312) 的云端工作区。验收使用隔离项目、假模型与模拟外部服务，复用现有认证入口及运行查询。上线前在实际客户端重复 UI 路径，并以运行编号和操作编号核对界面与业务结果。

- [ ] **工作台与工具插件。** 用产品、测试和兼任角色账号核对工具可见与可用范围；切换分类、收藏并重开客户端；用项目级工具定位授权项目。测试新增、停用和回退一个模块，核对卡片、可用状态和运行版本。撤权后通过旧收藏、直达链接及 Agent 调用均被拒绝。窄窗口和键盘可操作。
- [ ] **日程与事项回归。** 从独立入口打开已有日程，核对原周视图、单日视图、安排事项、拖拽改期和关联回跳。尝试调整项目里程碑，确认只修改项目计划；经日程页显式保存后，才生成相应安排。
- [ ] **项目统筹。** 准备两个有权项目和一个无权项目。构造跨项目依赖和一条验收阻塞，检查风险、里程碑、待跟进人和原阶段跳转。登记跟进并重放同一操作，仅保留一条跟进与提醒；模拟逾期、授权升级、责任人处理及后续恢复，核对时间线。撤权后直达链接和 Agent 查询均受限；用仅有统筹权限的账号尝试改需求、改验收结论或跳过质量放行，应被拒绝。小团队兼任可走完原阶段流程。
- [ ] **统筹界面闭环。** 在两个授权项目中注入同一跨项目阻塞。进入总览看到上游环境风险及下游候选影响；打开阻塞可核对原需求、阶段、负责人和回执。取消提醒或升级时零发送，截止前不显示升级操作，收到有效回应后按实际状态处理。研发回执到达后仍显示待阶段负责人确认；测试确认并继续后原候选和当前阶段保持一致，里程碑刷新为实际验收状态。
- [ ] **Issues 集合与状态。** 用两个授权仓库及一个无权限仓库构造跨页、同编号、开放、已完成、不计划处理、未加入 Projects 与 Pull Request 样本。核对仓库 Issue 集合与计数、各分组、关闭原因、标题与编号搜索和详情定位。关闭详情后保留筛选与位置。取消 Projects 授权后仍可读取已获准的仓库 Issue，并按开放与关闭分列。
- [ ] **Issues 只读与失败。** 核对看板动作仅查询，修改入口打开对应 GitHub 原文。外部修改后刷新，确认变动与原文一致。断网或限流时区分空库和过期快照；撤去仓库访问权限并检查卡片、详情、直达与缓存，确认没有未获授权的内容。
- [ ] **项目时间线和定位。** 两条需求并行，分别产生交接、返工、验收和构建事件。进入项目默认显示该项目时间线；点击历史交接定位当时阶段，点击进行中的需求定位当前节点，返回恢复原滚动位置。刷新或重连回放同一事件时仅展示一次。项目页和需求群展示相同阶段状态与证据。
- [ ] **推进、返工与恢复。** 从产品确认到研发交接、测试退回、研发重交、独立验收和质量放行走完一条需求。故意注入缺业务决定、缺证据、无权限及过期执行者，核对无法跳过对应条件、正确提醒和恢复原阶段。人工接手后旧执行回调不能覆盖新结果，重放交接时仅通知一次。
- [ ] **阶段详情和证据版本。** 四种详情均可按需打开，能从必过条件定位固定版本与原始证据。更换候选或影响验收的规格后，旧通过结果留存并标为失效；当前版本通过所需检查之前，完成度与交付均显示阻塞。模拟空数据、原件权限撤销和读取失败，分别得到可辨认提示。
- [ ] **上下文与权限。** 用含大量历史记录的项目启动阶段运行，核对初始输入与后续实际读取。检索问题只读相关授权片段并返回可回查来源和版本。测试同名跨项目文件、无权群和权限收回后的续跑。注入新旧决策冲突与必需资料缺失，核对展示有效版本并把依赖步骤标为待确认。
