## 入口与用户流程

| 场景 | 页面与行为 |
| --- | --- |
| Windows 首次使用 | 默认进入本机空间，从头像菜单或「设置 → 账号与空间」添加账号。进入云端工作区或接受项目邀请时，如未登录，展示登录入口并保留原目标。 |
| 登录 | 输入邮箱，明确申请验证码，输入收到的六位码。复用 Supabase Auth 与现有的账号核验服务。首版沿用邀请或管理员开通账号的方式，验证码登录只用于已开通账号。服务未配置时提示本机可用及部署状态。 |
| Windows 验证后 | 展示当前空间、目标账号和「待重启切换」。用户选择「重启并切换」时提示结束本机任务并收尾。选择「保留当前空间」时回到原空间，已验证的账号留在本机列表。原后台退出后新后台才可读取目标空间。 |
| Windows 设置 | 「当前空间」显示数据所在位置和云会话状态。「此设备上的账号」支持添加账号、切换、重新登录和退出云端，可显式返回本机空间。进入账号后，可在「我的 Agent」查看分身的身份、个人偏好与各项目的能力。项目管理员在成员页管理岗位和授权。 |
| 移动 Web/PWA | 进入云工作区时登录同一 tebb 账号，验证后回到原本有权打开的工作区、邀请或任务。账号切换先结束旧客户端订阅并隔离缓存，再加载新账号。云端运行继续归原账号。 |

## 身份、工作区与连接

- **tebb 账号**由 Supabase Auth 的已验证用户标识确定；邮箱用于登录与展示。项目成员关系决定角色和可见范围。验证邮箱后，项目邀请按目标邮箱、有效期、项目和服务端登记的授权确认加入。域名相同的用户仍按邀请或管理员授予的权限加入。
- **工作区**区分设备上的本机空间、按账号独立的本机空间，以及云端工作区。登录和切换不转移聊天、模型密钥、飞书凭据或项目文件。确认的个人资料继续走[既有同步范围](../../PERSONALIZATION_SYNC.md)。切换时冻结原运行归属、清理旧前端订阅和缓存键；失败时展示实际仍运行的空间，重开后用同一操作编号核对。
- **GitHub 仓库授权**放在「项目 → 设置 → 连接」，由项目管理员绑定仓库。GitHub 读取权限单独核验，首版建议使用 GitHub App 的按仓库授权，权限限于 Issues 只读；需要按 Projects 字段分组时再核验对应 Projects 读取权限。私有数据查询同时核验 tebb 项目成员、项目的绑定范围及当前 GitHub 用户有权读取的仓库；服务端缓存沿用相同边界。撤权后旧链接和缓存同样受限。连接 GitHub 仅用于项目数据访问，tebb 登录沿用邮箱。

## 一人一个 Agent

- **绑定。** 一个云账号在当前部署内绑定一个长期存在的个人 Agent。以验证后的用户标识建立唯一绑定，首次进入时幂等创建；邮箱、显示名、设备或会话变化均沿用原 Agent 标识。设置页显示「我的 Agent」，需求群加入成员后可按岗位分派给该成员的 Agent。个人 Agent 可以参与多个项目和群，每次运行按项目、需求与阶段独立保存上下文和证据。仅本机使用沿用现有本机空间与本机伙伴。
- **执行与决策。** 阶段由对应岗位成员的 Agent 执行和交接。研发与独立验收由不同成员负责，阶段分派与验收提交按候选的实现记录核对实际成员与 Agent。同一个候选的实现成员无法提交该候选的独立验收结论。测试 Agent 在固定候选上复跑，也可以在独立验收目录写入自己的用例和证据。
- **能力因人、任务与资源而异。** 例如林青的 Agent 负责研发，使用 OpenSpec 和定向自测；周宁的 Agent 负责独立验收，使用用例设计与复跑 Skill。每个成员可在模型和 Skill 目录中选择适合自身的配置。Agent 共用当前执行环境的工具目录，实际调用由 tebb 在 Pi SDK 工具边界按目标项目、仓库、目录、环境和动作核验授权。岗位用于分工与决策归属；Skill 和模型配置不会扩大资源权限。
- **撤权、恢复和交接。** 运行、产物与决定记录 Agent、账号、分派岗位及实际操作者。成员离开项目或改派时，失权 Agent 停止继续使用原项目资料或工具；接手成员的 Agent 通过授权的阶段交接记录恢复。原分身身份和个人会话归原账号，项目内获准证据继续按项目权限可查。

## 我的 Agent、项目成员与待我决策

| 页面 | 交互与生效规则 |
| --- | --- |
| 设置 → 我的 Agent | 显示本人及绑定的 Agent，提供团队可用模型、个人 Skill、添加 Skill 入口和项目授权摘要。保存模型和启用的 Skill 后，新运行使用对应版本；已开始的运行继续使用原配置，执行动作时重查当前资源授权。项目摘要显示授权来源及仓库、目录、环境和可执行动作。 |
| 项目 → 设置 → 成员 | 管理员选择成员、分配岗位并明确保存。项目权限按资源和动作配置，例如在研发目录写入、在验收目录写入、在指定沙箱执行。两个 Agent 可以调用同一个写文件工具，实际可写位置由该次操作与授权范围决定。变更记录操作者、对象、资源和前后值；撤权后的下一次受保护调用按新授权判断。 |
| 通知 → 待我决策 | Agent 需本人决定时，在项目、需求、阶段和当前运行的检查点上登记待决策记录，提示请求人、选项、取舍及复现或验收依据。本人选择方案后明确提交；决定及原始依据可从需求群查看。计划变更、升级、放行和发布按各自岗位权限办理。 |

决定绑定运行编号、阶段、检查点和请求版本。确认时核对本人身份、仍有效的岗位或决策授权，以及请求是否已被替换或处理。同一确认操作重试只返回原回执。服务持久保存决定后恢复原运行，续跑前重新核验资源授权和已完成步骤；授权缺失时显示「已确认 · 等待项目授权」并保留原检查点，满足后再继续。请求版本变化或改派时更新待决策项，保留旧决定供回查。

## Skill 目录与个人添加

- **官方目录**由 [tebb-skills](https://github.com/lkun-lea/tebb-skills) 独立维护，产品按[固定版本导出](../../DEVELOPMENT.md#官方技能源码与自定义技能)读取。**项目目录**由项目管理员指定授权仓库中的目录和版本。**个人目录**归当前账号管理，存放用户明确导入或采纳的 Skill。三类目录各有来源与版本，同名项可辨认；导入不覆盖官方、项目或其他账号的条目。
- 「我的 Agent → 添加 Skill → 从文件夹导入」选择包含 `SKILL.md` 的目录，预览名称、说明、引用文件、脚本和所需能力。检查格式和文件范围后复制到个人目录；越界引用、符号链接逃逸或冲突给出明确反馈。添加后在「我的 Skill」选择启用并保存，新运行记录所用 Skill 的来源与版本。启用 Skill 时，工具操作沿用现有资源授权。
- 「添加 Skill → 请我的 Agent 起草」复用已绑定的个人 Agent 和 Pi SDK，给它一个专门的 Skill 设计任务。用户描述触发场景、输入输出与约束，Agent 在私人草稿目录生成 `SKILL.md`、必要引用以及示例用例，列出预计用到的能力。预览差异并在隔离环境试跑，保留样本、预期、实际与工具回执。本人确认后才能加入个人目录，之后按需启用。发布到项目目录由项目维护者评审，官方发布沿用 tebb-skills 仓库流程。

## 会话与异常

- Windows 复用现有 AccountService 与当前 Windows 用户的 DPAPI 存储。界面通过账号接口获得会话状态，令牌和验证码正文不进入工作区、Agent、诊断输出或页面持久缓存。云端 API 核验令牌、工作区成员和资源权限；浏览器首版建议使用同源会话，Cookie 设置 HttpOnly、Secure、适当的 SameSite 策略，修改类请求另做来源及 CSRF 校验。
- 验证码请求绑定当前登录环境和邮箱。无效、过期和限流分别给出下一步；断线或回执不明时先核对原请求，用户明确重新申请后才发新码。登录后的目标只允许应用内路径，恢复前重查授权。
- 启动显示当前空间与云端连接状态。离线重开原空间时可用已存的本机数据，云端操作等待重新核验。退出云端清除本机当前会话，显示远端撤销结果；本机资料仍归该空间，其他设备会话按原规则保留。设备管理、公开注册和企业 SSO 另行评审。

## 验收

- [ ] Windows 未配置账号服务时可直接进入本机空间。用两个合成账号完成申请、错码、过期、断线核对、验证和切换；取消切换前后空间一致。注入后台退出失败与旧运行迟到事件，核对只写入原空间。
- [ ] 用同一真实邮箱在 Windows、iPhone Safari 和 Android Chrome 登录，按同一云运行编号查看已授权项目与任务。换成另一个账号，旧订阅、缓存、下载链接与项目邀请都按新身份校验。
- [ ] 离线打开原空间、重新认证、退出云端及远端撤销结果未知均有独立界面状态。核对本机资料可回查，云端任务按原账号继续，另一台已登录设备的会话保持有效。
- [ ] 用相同 tebb 角色分别连接有、无 GitHub 权限的用户，验证 Issues 的公开与私有仓库行为。撤去项目或 GitHub 权限后，原查询、卡片详情及缓存均拒绝；登录成功不会自动授予仓库访问权。
- [ ] 并发首次登录及跨端重登同一账号只得到一个个人 Agent 标识。两个账号的 Agent 标识、个人偏好和记录分离。本人成为项目成员后仍能选模型、启用 Skill 并保存，新旧运行可查各自模型和 Skill 版本。
- [ ] 用两个成员分别承担研发与独立验收。管理员保存岗位和资源权限后，两者可发现同一写文件与沙箱工具，分别能在获准目录执行。把目标改为无权目录或撤销授权再尝试，调用应拒绝；用实现成员提交同一候选的独立结论应被拒绝。项目成员页和调用记录能核对实际人、Agent、岗位及资源范围。
- [ ] 制造一条需要本人决定的运行。确认前相关动作停在当前检查点；其他成员确认、重复确认、旧版本确认分别得到正确结果。确认后核对运行编号与检查点，从后续步骤继续；故意撤回写入授权时保留「已确认 · 等待项目授权」，恢复授权后只执行一次。改派后新 Agent 从获准交接继续。
- [ ] 导入个人 Skill，验证选择目录、预览、保存和显式启用；用同名官方 Skill、越界引用、未授权脚本和另一账号测试来源隔离。让个人 Agent 生成新草稿并用固定样本试跑，留存差异和原始回执。取消或试跑失败时仍保留草稿，确认后只写入个人目录；项目共享另行评审。
