# 账号与登录设计

待评审方案。现有实现见[客户端账号与本机空间](../../ACCOUNTS.md)，跨端依赖见[云端与多端架构](../../CLOUD_MULTICLIENT_ARCHITECTURE.md)。[交互预览](account.html) · [可编辑源稿](account.fragment.html)。

## 入口与用户流程

| 场景 | 页面与行为 |
| --- | --- |
| Windows 首次使用 | 默认进入本机空间，从头像菜单或「设置 → 账号与空间」添加账号。进入云端工作区或接受项目邀请时，如未登录，展示登录入口并保留原目标。 |
| 登录 | 输入邮箱，明确申请验证码，输入收到的六位码。复用 Supabase Auth 与现有的账号核验服务。首版沿用邀请或管理员开通账号的方式，验证码登录只用于已开通账号。服务未配置时提示本机可用及部署状态。 |
| Windows 验证后 | 展示当前空间、目标账号和「待重启切换」。用户选择「重启并切换」时提示结束本机任务并收尾。选择「保留当前空间」时回到原空间，已验证的账号留在本机列表。原后台退出后新后台才可读取目标空间。 |
| Windows 设置 | 「当前空间」显示数据所在位置和云会话状态。「此设备上的账号」支持添加账号、切换、重新登录和退出云端，可显式返回本机空间。进入账号后，可在「我的 Agent」查看分身的身份、个人偏好与各项目的能力。项目管理员在成员页管理岗位和授权。 |
| 移动 Web/PWA | 进入云工作区时登录同一 tebb 账号，验证后回到原本有权打开的工作区、邀请或任务。账号切换先结束旧客户端订阅并隔离缓存，再加载新账号。云端运行继续归原账号。 |

## 身份、工作区与连接

- **tebb 账号**由 Supabase Auth 的已验证用户标识确定；邮箱用于登录与展示。项目成员关系决定角色和可见范围。验证邮箱后，项目邀请按目标邮箱、有效期、项目和服务端登记的授权确认加入。域名相同的用户仍按邀请或管理员授予的权限加入。
- **工作区**区分设备上的本机空间、按账号独立的本机空间，以及云端工作区。登录和切换不转移聊天、模型密钥、飞书凭据或项目文件。确认的个人资料继续走[既有同步范围](../../PERSONALIZATION_SYNC.md)。切换时冻结原运行归属、清理旧前端订阅和缓存键；失败时展示实际仍运行的空间，重开后用同一操作编号核对。
- **GitHub 仓库授权**放在「项目 → 设置 → 连接」，由项目管理员绑定仓库。GitHub 读取权限单独核验，首版建议使用 GitHub App 的按仓库授权，权限限于 Issues 只读；需要按 Projects 字段分组时再核验对应 Projects 读取权限。私有数据查询同时核验 tebb 项目成员、项目的绑定范围及当前 GitHub 用户有权读取的仓库；服务端缓存沿用相同边界。撤权后旧链接和缓存同样受限。连接 GitHub 仅用于项目数据访问，tebb 登录沿用邮箱。

## 一人一个 Agent

- **绑定。** 一个云账号在当前部署内绑定一个长期存在的个人 Agent。以验证后的用户标识建立唯一绑定，首次进入时幂等创建；邮箱、显示名、设备或会话变化均沿用原 Agent 标识。设置页显示「我的 Agent」，需求群加入成员后可按岗位分派给该成员的 Agent。个人 Agent 可以参与多个项目和群，每次运行按项目、需求与阶段独立保存上下文和证据。仅本机使用沿用现有本机空间与本机伙伴。
- **执行与决策。** 阶段由对应岗位成员的 Agent 执行和交接。例如研发 Agent 改代码并自测，测试成员的 Agent 依据固定用例独立复跑。成员在需要业务取舍、权限授权、质量放行、统筹升级或发布时收到带依据的决策请求，确认后由 Agent 从原阶段继续执行。日常读取、实现和验证按已授权范围连续推进。质量与测试沿用现有独立验收规则，要求不同执行身份的项目按其验收策略选派。
- **能力因人、岗位与项目而异。** 平台提供岗位模板，成员可在允许范围内选择模型、Skill 与偏好，管理员授予项目资源与工具权限。比如同一个 Agent 在桌面项目担任研发，可用 OpenSpec、授权目录写入和沙箱自测；在移动端项目担任测试，可读候选、执行固定用例和提交证据。一次运行以分派的岗位、项目、阶段、资源授权及当前工具权限的交集为准。个人偏好和 Skill 只影响行为，Agent 调用权限由 tebb 在 Pi SDK 工具调用边界核验。
- **撤权、恢复和交接。** 运行、产物与决定记录 Agent、账号、分派岗位及实际操作者。成员离开项目或改派时，失权 Agent 停止继续使用原项目资料或工具；接手成员的 Agent 通过授权的阶段交接记录恢复。原分身身份和个人会话归原账号，项目内获准证据继续按项目权限可查。

## 会话与异常

- Windows 复用现有 AccountService 与当前 Windows 用户的 DPAPI 存储。界面通过账号接口获得会话状态，令牌和验证码正文不进入工作区、Agent、诊断输出或页面持久缓存。云端 API 核验令牌、工作区成员和资源权限；浏览器首版建议使用同源会话，Cookie 设置 HttpOnly、Secure、适当的 SameSite 策略，修改类请求另做来源及 CSRF 校验。
- 验证码请求绑定当前登录环境和邮箱。无效、过期和限流分别给出下一步；断线或回执不明时先核对原请求，用户明确重新申请后才发新码。登录后的目标只允许应用内路径，恢复前重查授权。
- 启动显示当前空间与云端连接状态。离线重开原空间时可用已存的本机数据，云端操作等待重新核验。退出云端清除本机当前会话，显示远端撤销结果；本机资料仍归该空间，其他设备会话按原规则保留。设备管理、公开注册和企业 SSO 另行评审。

## 验收

- [ ] Windows 未配置账号服务时可直接进入本机空间。用两个合成账号完成申请、错码、过期、断线核对、验证和切换；取消切换前后空间一致。注入后台退出失败与旧运行迟到事件，核对只写入原空间。
- [ ] 用同一真实邮箱在 Windows、iPhone Safari 和 Android Chrome 登录，按同一云运行编号查看已授权项目与任务。换成另一个账号，旧订阅、缓存、下载链接与项目邀请都按新身份校验。
- [ ] 离线打开原空间、重新认证、退出云端及远端撤销结果未知均有独立界面状态。核对本机资料可回查，云端任务按原账号继续，另一台已登录设备的会话保持有效。
- [ ] 用相同 tebb 角色分别连接有、无 GitHub 权限的用户，验证 Issues 的公开与私有仓库行为。撤去项目或 GitHub 权限后，原查询、卡片详情及缓存均拒绝；登录成功不会自动授予仓库访问权。
- [ ] 并发首次登录及跨端重登同一账号只得到一个个人 Agent 标识。两个账号的 Agent 标识、个人偏好和记录分离。让同一 Agent 分别作为桌面研发和移动端测试运行，核对其 Skill、目录、命令和验收权限随项目与分派岗位改变，测试运行拒绝写入研发目录。
- [ ] 用真实需求串联研发 Agent 自测、测试 Agent 独立复跑与人工决策；注入未确认的放行或升级动作，确认只产生待决策记录。人工确认后从原阶段恢复；撤权或换负责人时验证旧 Agent 无法续用原工具，新 Agent 可从授权交接继续。
