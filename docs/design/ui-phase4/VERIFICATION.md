# 第四批 UI 与人工反馈修复验收

2026-11-06，#290 / #291 / #292。使用当前标准 Vite 配置的1432端口、Windows Chromium headless shell 1228，1440×1000、1280×900及600×900。页面为真实 App 的内存看板/日历，原生界面最终复测由用户执行。

## 用户反馈及处理

| 反馈 | 修复与证据 |
| --- | --- |
| 浅色卡片悬停后与背景融为一体 | 原3%前景混色使卡片近似页面背景；改为语义抬升表面。浅色悬停实测白色，对比页面 #f5f5f3；深浅均断言首通道差至少8，保留去边框。 |
| 日程拖放后滚动条跳动 | 保存改变 day 会重放旧定位，且同周也调用 changeView；桌面浮动编辑器还会再次 scrollIntoView。现仅主动定位滚动，同区间不重建，浮动编辑器只无滚动聚焦。已有日程同日/跨日保存采样均无隐式定位/聚焦调用，scrollTop和scrollHeight保持不变；左侧事项拖入后草稿可见，scrollTop不变。Chromium未复现用户看到的原生自发上下跳动，但确认并移除了重复滚动调用，原生结果待用户复测。 |
| 无法打开合成资料 | 移除对原生注入快捷键的依赖，开发态提供可见按钮。按钮等待真实工作台就绪，通过公开预览入口打开合成资料及网页标签；原验收窗口刷新后可用。 |

本批还统一了日历、安排事项、看板与详情的12/14/16px字档和24px主标题、普通容器/控件去边框、事件去左彩条及状态语义色。15分钟时间块在18px视觉高度内完整容纳12px/16px行高标题，日期和实际时长未改变。高对比使用系统边框例外。

## 检查结果

- 前端完整测试309/309通过，0失败、0跳过；最终按 package.json 的全部测试文件执行，限制 Node test-concurrency=4。标准 pnpm test 同一套测试也完成过309/309。
- TypeScript检查与标准生产构建通过；保留已有大于500kB的分包警告。正常生产资产不包含“打开合成资料”工具。
- 浏览器33项拖拽/主题扩展检查、11项表单/视图检查、2项补充检查通过，无 pageerror。另记录两条已有日程拖放的稳定滚动采样。
- 深浅看板抓起、日历归位和浮动编辑器共6次 clip-audit，全部 cut=0、hidden=0。检查时发现编辑器阴影位于有滚动裁切的内层，已移至外层并缩小阴影，重新审计通过。
- 标准服务页面响应、前端修改后的缓存失效、排除原生监听均通过实际服务测试；不使用 watch:null 替代标准配置。
- 隔离原生验收宿主构建和 cargo check通过。宿主复用生产 side_browser，实现未另写一套；只记录构建通过，不记为原生网页布局/拖动交互通过。

数据、每项结果、滚动样本、宿主摘要及交付源码摘要见 [results.json](results.json)。入口和复测操作见 [原生验收说明](../../UI_NATIVE_CHECKS.md)，视觉及滚动职责见 [业务页面视觉](../../UI_BUSINESS_PAGES.md)。

## 边界与保留

用户接手后未继续自动操作桌面。原生拖动、缩放、网页位置同步和点击偏移、系统触控/IME及真实服务回执仍需用户复测；既有模拟服务的明确失败/未知回执测试继续通过。未调用真实模型或向飞书写入。

保留用户原有未提交的 AGENTS/GLOSSARY、工作区配置、Cargo/build/main及Python等改动，只提交本批文件/片段。不发布版本、不改权限协议、不增加依赖；删除被替代的注入快捷键实现及去边框后无效的 border-color，测试临时模块/缓存按创建路径清理。
