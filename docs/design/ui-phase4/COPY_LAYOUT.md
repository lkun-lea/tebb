# 提示文案切换导致的布局位移

2026-11-06，继续 #292。用户在原生验收中指出，“安排事项”的文字变化可能导致一次上下跳动。之前的 scrollTop/scrollHeight 采样未覆盖局部元素位置，不能据此排除布局位移。

## 复现与修复

在真实内存日历、1440px视口下，提示由“拖动抓手放入时间轴，或点击安排时间；保存前都是草稿。”变为“请先结束当前编辑或核对原操作。”时，段落从两行变一行：

| 度量 | 修复前 | 修复后 |
| --- | --- | --- |
| 提示高度，正常→禁用 | 40.78125→20.390625px | 40.78125→40.78125px |
| 列表视口顶部，正常→禁用 | 463.78125→443.390625px | 463.78125→463.78125px |

`UiStableText` 用同一个Grid格叠放参考文案和当前文案，参考节点保持布局但不可见、aria-hidden且不能接收指针。Grid按当前字体与可用宽度自然保留参考尺寸，当前可见节点保持不变，只有文字更新。日历顶部状态行也采用相同规则，普通短状态不再压缩说明区域。

没有JS计算高度、固定像素高度、逐帧回设滚动位置或省略正文。真正长于参考的消息仍可自然扩展，错误、未知回执与控制器状态不变。窄窗表单进入可见区域的主动焦点行为仍保留。

## 验证

- 深浅两主题，1440/1180/840/600/480/400px共12组真实浏览器用例。
- 每组测正常、打开草稿后的禁用、取消恢复、键盘抓取/取消，比较提示高度、状态行高度、列表相对位置及日历相对位置，允许误差小于0.1px。
- 12组均通过；隐藏参考节点不可见，实际显示只包含当前提示。组件行为测试覆盖参考节点的aria隐藏与可见节点复用。
- 完整前端回归310/310通过，类型检查与生产构建通过，保留既有大包警告。没有重新操作用户桌面，原生结果仍由用户复测。

数据见 [copy-layout-results.json](copy-layout-results.json)。[浅色正常](copy-normal-light-1440.png) / [浅色禁用](copy-disabled-light-1440.png)，[暗色正常](copy-normal-dark-1440.png) / [暗色禁用](copy-disabled-dark-1440.png)；另保留600px截图。

## 可重复入口

先启动标准开发服务，浏览器脚本复用外部测试环境的 playwright-core 与 Chromium，不改变项目依赖。设置 `UI_PLAYWRIGHT_CORE_PATH`、`UI_CHROMIUM_PATH` 和新的绝对 `UI_QA_OUTPUT` 目录后，在仓库根运行：

```powershell
node client/tests/calendar-copy-layout.browser.cjs
# 可选 UI_BASE_URL，默认 http://127.0.0.1:1432
cd client
pnpm test
pnpm exec tsc --noEmit
pnpm build
```

脚本输出每组 PASS、JSON与合成页面截图。原生验收窗口刷新后复测安排事项、拖放及保存阶段，无需重建宿主。
