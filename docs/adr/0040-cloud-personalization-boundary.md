# 云端个性化使用 Supabase 身份与权威记忆记录

2026-11-03，用户确认首版即支持云端多账户及跨设备，并采纳 Supabase Auth + PostgreSQL/pgvector + LangMem 的方向。现有本机 user 作用域不是账号，不能把 facts.json 的 owner 或本机 RPC token 当作云端登录身份；云端记忆记录以已验证用户为归属，保留 tebb 自己的确认、证据、版本、冲突和遗忘契约，Atlas 继续拥有对话与工具执行。

同步只覆盖实用画像、偏好与已确认长期记忆，情绪仅用于当前会话，长期性格推断后续可选。记录写入经受控函数、版本检查与幂等回执，按用户串行分配变更游标，删除保留无正文墓碑；不以设备时钟覆盖冲突，不让旧离线写入复活删除。采用 Supabase 而非自建身份系统；暂不引入图数据库，也不另设一个自动写入的记忆权威系统。

用户尚无云项目，先交付独立部署包和接入契约（#241）；生产账号切换、本机数据隔离/明确认领、离线队列及 LangMem 适配由 #238 后续实施。托管项目先使用邮箱验证码；OAuth/链接登录若加入则使用 PKCE。LangMem SDK 版本须经现有模型传输、预算和调试入口的适配验证后固定，当前不将其列为已接入的运行时依赖。完整依据见 [方案](../USER_PERSONALIZATION.md) 和 [部署说明](../../supabase/README.md)。
