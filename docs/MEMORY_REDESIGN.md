# 记忆重整首版对齐（#217）

2026-11-01 对齐、11-02 实施：用户降低黑屏优先级，优先重整记忆，并要求展示实际发给模型的完整记忆及提供调试能力。沿用本批统一采用推荐方案的授权，界面采用已确认的「调用检查台」。本文为首版契约与实现说明，最终验收记录见 #217。

## 四项规则

| 事项 | 推荐首版规则 |
| --- | --- |
| 作用域 | 用户全局、项目、伙伴、会话分别指定归属。默认最小相关范围；项目记忆不自动跨项目，伙伴私有偏好不自动给其他伙伴。人格、任务状态、外部授权不是可随意改写的记忆。 |
| 读写与召回 | 各入口使用同一记忆服务与选择规则；稳定ID、版本、来源、状态可查询。保存后重新组装下一次请求；本次冻结版本不变。每次记录实际选中/排除条目及原因，修复全局事实可写但协作没有统一注入的断点。 |
| 生命周期 | 明确保存/记住可生效；自动提炼先成为待确认候选。更正保留版本，矛盾显式标记，不能用一句话相等替代冲突处理。支持停用、期限和撤销。区分停止后续使用与清除来源/派生摘要/历史快照等副本，不把删除一行记录描述成已经全面遗忘。 |
| 用户核对 | 用户可查这次用了哪些、为什么使用、来自哪里、何时/由谁修改；从注入条目回到来源编辑或停用，再核对下一次实际请求。未知归因和未记录请求明确显示缺失。 |

当前明确更正优先于旧偏好；其他事实冲突不能静默按最新时间覆盖。检索到的记忆属于背景资料，不得扩大本轮权限或覆盖当前明确目标。已有用户原始数据保留，未经明确的数据处理方案不自动清空或批量重写。

## “完整记忆”的展示契约

用户要看到的是一次模型调用实际发送的完整上下文；已保存的长期条目只是其中一部分。入口以此为主，伙伴偏好回归“记忆来源”的一个分类。

默认选择最新主调用，可切换会话、任务、主/子伙伴、阶段与具体调用。按顺序展示全部消息、角色、工具调用/结果和工具定义，并保留完整原始请求JSON入口。内容按来源清单导航：系统规则、全局记忆、项目记忆、伙伴偏好、会话摘要、未压缩历史、本轮输入、资料及工具回执。分类依赖组装时明确的来源记录，不靠扫描文字猜测。

条目展示原文、作用域、来源链接、版本、生效状态及选取原因；未选条目显示被排除的原因。来源清单和最终发送内容通过稳定标识及内容摘要对应；调用前的摘录、压缩、容量准入后，以实际发送边界为准。

“完整”仅覆盖应用可观察到的实际请求。服务商隐藏提示、内部推理和后续尚未发生的工具结果不可观察，不能补造。旧调用缺少来源记录时仍可展示现存原始请求，但归因显示未知，不能拿当前伙伴配置倒推历史。暂停记录/文件丢失时明确显示未记录/缺失。

长内容可按需展开与分页，但必须能看全，不能把摘要/截断当原文。输入计数来自服务回报或匹配分词器；未知保持未知。

## 三种调试视图

1. **已发送**：只读、不可原地改写。以真实调用编号与冻结快照核对，不用聊天列表拼回过去请求。
2. **下次发送预览**：使用实际组装器，以当前会话/伙伴/记忆版本与草稿只读组装。展示内容及差异，不发模型请求、不写长期记忆；未来路由/工具结果明确尚未知。发送时复验版本，变化后需要重新预览。不是简单对上次请求追加草稿。
3. **独立试验**：复制可观察输入建立新试验，可临时启停记忆、调整文本，查看与原调用的差异。默认只组装；明确试跑才产生有界模型调用。真实写入工具不登记，不重放日历/飞书/终端等历史操作，不自动更新生产会话、长期记忆或原任务状态。结果和调用编号独立，只有明确“应用修改”才影响未来生产请求。

系统规则、真实工具回执、业务状态和权限不能通过“编辑记忆”伪装成新的生产事实。试验中的文字覆盖须明确标为试验输入。需要验证记忆写入时，使用独立合成存储和假工具，不以真实用户数据作为测试写入目标。

## 编辑、遗忘与隐私

从发送内容进入来源编辑，保存产生新版本；已启动任务继续使用原版本。断连、冲突与部分保存使用原请求编号只读核对，不自动重放。

“停止使用这条记忆”与“清理相关内容”分别提供。前者控制后续记忆选择；如果原聊天/摘要仍会把相关内容带入请求，必须列出残留来源并提示处理，不能声称全面遗忘。后者先预览可核实关联的原文、摘要、索引与快照范围，分别报告清理结果、未知及不受应用控制的副本。不得承诺模型服务端已删除。

查看与本地预览不上传内容。连接鉴权头、Cookie、模型连接密钥不进入追踪展示；用户自行放进消息正文的秘密可能仍在真实内容中，不声称自动全量脱敏。复制/导出由用户明确选择范围，试验发送前展示将发送的内容和目标模型。

## 复用与交付顺序

复用原协作事务、普通会话服务、上下文组装/容量准入、发送边界记录、认证RPC及任务/调用链。知识库检索和项目聊天检索仍是不同资料来源，是否参与召回应明确标识，不把整个memory目录都叫长期记忆。不另造Agent、模型调用环或第二套调试记录；存储细节在数据方案核对后确定。

顺序：统一领域/接口及数据处理规则 → 统一读写与来源清单 → 用户实际发送检查、来源编辑及真实组装预览 → 独立试验与有限真实模型验收。替换当前“记忆固定打开伙伴偏好”的入口，避免新增一个含义重复的面板。

验收必须核对：

- 同一条记忆跨普通助手/伙伴/后台任务的使用与作用域隔离；无相关条目时不伪造命中。
- 更正、冲突、过期、停用、已启动任务快照和副本清理说明；历史与本次注入分别核对。
- 页面可查看的完整内容与实际发送请求逐项对应，包括主/子任务及多轮工具结果；记录缺失和未知归因不补造。
- 真正组装器的预览与无变化条件下发送内容一致，版本变化可检测；历史JSON不可直接改写。
- 预览零模型调用/零生产写入；独立试验零真实工具写入、结果不自动写回；有限真实模型验证真实召回与使用结果，不以HTTP成功或非空文本代替。

## 当前实现与数据所有权

`facts.py` 继续拥有同一份 `memory/facts.json`，没有新增事实副本、向量库或双写。条目支持 scope、owner、version、state、source、versions、expires、key；已有原文不批量清空或迁移，读取不改文件。未标归属的事实属于用户全局，未记录的来源/修改信息显示未知。模型新建仍限80字及有效本轮原话；检查台人工编辑上限2000字。

`memory_selection.py` 为普通助手、协作伙伴、后台任务和预览提供同一选择规则。伙伴配置仍由协作 SQLite 事务拥有，原 memory 字段加状态、版本及历史；选择器把它作为伙伴来源，停用保留原文。每个新 run 冻结选择清单；保存不会改已启动任务。人格、项目说明、业务回执、聊天摘要分别标记，不变成事实条目或权限。

候选需在检查台确认；工具未检测到明确“记住/记下”等要求时只生成候选。原话检查是连续片段核对，不是语义蕴含证明。更正使用准确 id/version 并保留旧版，模型工具 `corrects` 也要求本轮明确更正；停止使用使用准确身份/版本，不再整句批量删除。冲突按用户指定的相同主题键保守标记，待明确更正；不声称自动发现所有语义矛盾。

`context_sources.py` 在组装处记录消息来源与记忆片段位置；通过消息内容摘要穿过 Atlas 投影及任务 JSON。`agent_debug` 在 HTTP 发送边界复核摘要，记录完整请求与对应清单。无法匹配的片段标记未知，不算确认采用。原始消息、工具调用/结果、工具定义始终有完整展开入口。

预览复用 `Collaboration._apply(..., dry_run=True)` 和工作进程的首调用组装；不创建生产 run、任务或模型请求。它带上当前输入框的模型、目标、技能、附件和采样选项，覆盖当前已存在会话的新消息。未保存新会话及正在运行任务的补充暂不做预测。发送按请求编号去重，并校验记忆/会话/参数/模型路由/容量/分词资料/输出策略；变化后拒绝发送并要求重新预览。未来路由及工具结果未知，生成上限由实际预算准入。

独立试验复用 TaskManager、CollaborationLLM、ExecutionLLM 与发送边界记录：一次模型调用、90秒、0执行工具，无额外收尾调用。临时覆盖仅针对来源已核对的记忆片段，版本为试验版本；系统规则、回执等不能借此改成生产事实。结果、实际发送快照及原调用关联独立保存；生产会话、记忆和原任务不自动写回。取消、状态和断连按原操作编号查询，不再次发起模型请求。

清理先列出可核对的本机调用副本；只有明确勾选后才删除所选文件。来源及旧版本须先停用才能清理。进行中调用跳过，部分失败逐项保留。原聊天、摘要、任务输入/输出、缺少元信息的记录、晚到文件及服务商副本可能仍在；调用索引保留缺失状态，不承诺全面遗忘。

## AI 调试入口

使用现有本机认证 RPC；浏览器协作能力令牌不开放这些方法。模型连接头/密钥不进入追踪，正文中的用户秘密仍可能原样出现。下列为 RPC 的 args，conversation 取 `load_collaboration` 的真实会话编号：

```json
{"conversation":"<conversation-id>","action":{"type":"catalog"}}
```

| memory_debug action.type | 输入与结果 |
| --- | --- |
| catalog | 可指定 agent_id；返回当前作用域、采用/排除条目及原因。它不是历史请求。 |
| edit | change 含操作type、id/version、operation（32位新十六进制ID）、text/scope/owner/key/expires；断连先 catalog 核对。 |
| preview | send 为当前 send 动作的 text/target/mode/model_id/skills/attachments/sampling；返回 request、sources、revision、原 action。 |
| send_preview | 原 send、revision；同 request_id 核对，不修改正文重试。 |
| trial_prepare | call_id、overrides（条目ID映射到临时文字，null停用）；只组装，返回目标、输入、差异、revision。 |
| trial_run | 原 call_id/overrides/revision、operation；返回 task_id；最多一次模型调用。 |
| trial_status / trial_cancel | task_id，或原 operation；核对任务真实状态、结果和实际发送快照。 |
| cleanup_preview | id；返回可核对副本、残留及 revision，不删除。 |
| cleanup_apply | 原 id/revision、明确选择的 calls、delete_source；逐项报告实际结果。 |
| open_source | id、可选历史 call_id；只打开已记录且仍存在的来源会话。 |

历史调用继续用 `load_context_debug` / `get_debug_call` 查看。没有文件或来源时保持缺失/未知。完整原始内容保存在既有本机追踪中，预览与试验不建立第二套记录系统。

隔离回归与任务质量验收：

```powershell
# 设置 DESK_COMPANION_DATA_DIR 到新的临时目录；使用已经固定的 Atlas 源码。
python scripts/ci_checks.py test --output <新的回归目录>
python scripts/eval_agent.py --output <新的模拟验收目录> --case memory_global --case memory_project --case memory_foreign_project --case memory_disabled --case memory_trial --limit 5 --samples 1 --timeout 90
# 明确真实模型验收才添加 --live；先在独立私有数据目录仅配置选定模型连接和网络策略。
# 不复制用户聊天、日程、飞书/MCP凭据；不得向真实外部业务服务写入。
```

五项固定任务最多6次调用。验收同时核对实际 JSON 答案、发送边界摘要、作用域排除、未登记工具，以及试验未改原记忆；所有成功、失败和取消保留，不以 HTTP 成功或非空正文代替任务结果。用量不完整时保持未知；不推算费用。最终清单与尚未验证的浏览器范围见 [交付清单](COMPLETION_MEMORY_217.md)。
