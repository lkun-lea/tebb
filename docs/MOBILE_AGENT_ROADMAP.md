# 手机主聊、个人助理与本地数据

2026-11-25 核对。移动端总入口为 #313，云端运行时为 #312，个人云聊为 #321。首版面向同账号的一台 Windows 和 tebb 自身会话。

## 当前产品

Android Compose/MVVM 已提供可跳过的邮箱验证码登录、访客本地聊天、听写草稿、局域网配对与原任务回复。手机云聊固定使用 mobile-main；PC 云聊以账号与会话隔离，每次提交取得 run_id。模拟器已验证访客与本地问答；真实邮箱登录、PC 关机后手机取回该 PC 云会话的全链路仍待验收。现行配对见 [Android 任务回复](ANDROID_TASK_REPLIES.md)，云端试点见 [部署记录](../deploy/README.md)。

## 目标职责

| 所有者 | 状态和行为 |
|---|---|
| Windows | 原始资料、目录授权、索引、模型 Key、本地执行记录与问题版本。主动连接 ECS，变化时上报获准的最小投影。 |
| ECS | 校验账号与设备归属，路由事件与回执；云端执行用户明确提交的云聊任务。Windows 私有资料走独立中转通道，隔离 demo 中仅传密文。生产密文暂存时长、撤销与清理、配对密钥建立和恢复须先确定。 |
| Android | 按账号缓存获准卡片、同步游标、来源时间、带版本的草稿。主聊汇合来源，展示待答与结果；待答清单索引同一问题。目录材料留在其获准设备，发送给云模型须单独授权。 |

同一 conversation 下可有多轮 run；request_id 用于同一次提交重试，事件游标用于断线续读，问题版本用于防止旧答复误投。事项可关联多个 run。用户点发送后的中转回执与 Windows 已接收分开，离线自动投递取决于密文暂存策略。Windows 离线可看手机已有缓存；首次访问从未授权同步的最新本地资料须等待电脑上线。

## 推进顺序与验收

1. [只读状态中转 #322](https://github.com/lkun-lea/tebb/issues/322)。先跑隔离 demo，再集成 Windows 主动上报、手机本地缓存、事件续读、权限撤销。用蜂窝网络验证离线显示上次状态、重连撤卡。热缓存首卡、在线变化、未缓存索引查询的建议 P95 分别为 200 ms、1 s、2 s，尚未实测。
2. [云端会话接续 #323](https://github.com/lkun-lea/tebb/issues/323)。可与第一步独立验证。PC 提交后 Android 用同账号发现该会话，取回同一 run；继续聊产生新 run；用另一账号访问被拒。最后关闭实际 PC 验收。
3. #313 主聊聚合。用一张卡复现直接引用、目标消歧、按任务保存草稿、过期问题与重复回传。明确引用后才改变回复目标，普通进度留在详情。
4. #313 / #238 个人助理。首例为“今天有什么事在等我”：从已有业务事项生成有来源、等待对象、更新时间的卡片；手机选择稍后提醒，电脑不重复打扰，另一端已处理后原卡撤下。区分记忆有效期、作用范围和行动权限。
5. #312 单设备执行。先核对 #317 / #318 的既有领取、恢复与授权实现。用隔离文件验证只读任务、离线排队、撤权及重复回执，再接入产品。租约到期后核对原执行结果。

## 第一个 demo 的证据与范围

仓库根目录运行：

```powershell
uv run --locked python -m unittest tests.test_mobile_status_relay_demo -v
```

用隔离模型产生真实协作服务的 needs_input 投影，两只独立 HTTP 客户端分别充当 Windows 和读取端。模拟 ECS 只保存加密快照，发送端关闭后能读回，错误密钥解密失败；连续读取获得同一问题；原运行接受回答后再次上报，读取端看到空列表。模型、网络中转与预配共享密钥均为测试替身。此项尚未覆盖真实设备注册、网络乱序、原生手机缓存、真实 ECS 断电恢复或性能验收。

### 本地语义检索评测（#326）

在安装项目 knowledge 扩展且已下载 bge-small-zh-v1.5 的 Python 环境运行 `python scripts/eval_plan_recall.py`。脚本使用八份合成方案，按原词、口语、模糊时间、同名线索和无答案五组输出 JSON。两种检索均在进程中运行，并在返回候选前按现存来源与当前授权过滤。测试还会在索引建好后删除和撤权，再用原词复查。

本机本轮 SQLite FTS5 前五命中 2/4，本地 BGE 混合检索 3/4，首项误召均为 0。能提供最新决定原文的题数分别为 2 与 3；这是送入回答的证据覆盖率。无答案题均返回空。热查询五次的样本 P95 约 0.1 ms 与 57 ms，平均提供原文 11.8 与 17 字，计时不含建索引和加载模型。混合召回多找回「夏天讨论的手机离线读文件」，仍漏掉「手机怎么接着处理电脑上的工作」。样本规模不足以估算用户历史上的命中率或延迟分布，首版保持本机检索，无需部署专用向量数据库。这一脚本只运行检索和证据选择，未调用生成模型。


### 已接入的用户入口

- PC 在「伙伴聊天 → 最近」搜索后点「查看时间线」。文件变更展示当时记录的路径和版本，任务回执带运行编号与调用编号。没有时间的排到末尾。选择共享，才允许当前配对设备接收此会话最近 16 条留存材料，每条最多 400 字；手机显示已保留数量及截断提示。每台电脑最多同时共享四段会话。
- Android 的「已共享方案」可离线回看带时间和来源的缓存，也可查看其他已授权的同事项或同项目会话。启用近期推荐后，首页显示最近一周的已共享工作，用户可核对、引用到本地草稿或纠正。待答建议绑定会话、任务和问题版本。长期偏好沿用 #238 的确认流程，这些观察不会改写偏好。账号切换后各自持有本机消息和草稿；旧版无账号标记的本机历史留在原设备本地入口。
- 手机主聊与待答清单消费同一版本的 Windows 快照。明确委托沿用工作事项、负责人、期限、运行关联和回执。手机改期一小时后，两端待答入口同步隐藏；已关联事项都完成或归档后撤卡。旧引用上的草稿可手动保留或取消，确认发送须核对原运行。网络恢复本身不会发送草稿。
- 登录后，「我的电脑」默认经 ECS 读取同账号 Windows 的加密在线标记，45 秒过期。首次在同一网络配对，在 Windows 明确选择「配对并通过 ECS 加密接续」。之后手机换网可通过 ECS 取得 Windows 状态、延后提醒或向原问题回复。普通「允许配对」沿用设备本来获准的直连。原有直连配对可解除并重新配对来启用中转。设备或密钥丢失也走重新配对。资料随配对授权撤销，离线手机在收到更新之前只能看到旧缓存，离线超过七天的缓存会在下次读取或前台轮询时清除。

## 手机主聊的模型来源与跨端验收（#341）

在 Windows 的「设置 → 账号与空间 → Android 手机配对」批准加密接续，勾选共享当前 HTTPS 模型地址和 API Key。手机登录账号与 Windows 配对账号须一致。手机收到端到端加密快照后，通过 Android Keystore 加密保存配置。选「本地」发普通消息，手机直接向该服务发送正文和最近的普通聊天上下文；服务可达即可回答。切到「云端」走 tebb ECS 的免费 Qwen。星期、时间和待答快捷问题可在手机上离线处理。每条新消息在入库时记录执行来源。撤销模型共享会在手机下次成功同步时清除配置，移除本机配对也会清除配置。如需立即吊销仍处于离线状态的设备所持密钥，应在模型服务处轮换密钥。

验收时在独立 Windows 工作区登记资料并创建一条可手动触发的自动化。共享通用伙伴会话并授予手机任务权限，在 MuMu 的「知识库」请求按名称重命名资料，再从「自动化」请求运行指定规则。Windows 端核对来源编号、标题、版本和自动化执行编号，读取自动化最终运行的答复。撤销 Agent 权限后再次提交，应保留草稿，Windows 运行数和资料名称都应保持原值。配对协议与来源版本可用 `python -m unittest tests.test_paired_calendar_demo tests.test_material_sources` 复验。
