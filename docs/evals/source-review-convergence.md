# 源码解读的收束与跨仓验证

## Gugu-web 旧轨迹复盘

最早足以交付有源码依据的入门概览的是第 8 轮结束。第 4–5 轮的 README 和开发约定说明产品目标；第 6–7 轮只有包清单和目录。第 8 轮实际读到前端 main.ts 的 L4、11–12、28–40，能展示 Vue 如何创建应用、安装路由、挂载到页面。同轮 backend/app/main.py L6、20–33 能证实 FastAPI 和主要路由模块的引用。凭这些材料可以用前端启动路径解释架构，不宜据此宣称具体浏览器请求已经如何穿过代理到达数据库。

| 轮次 | 后续动作 | 对原题的贡献 |
|---|---|---|
| 9 | Agent README 和 compose 配置 | 可补充子系统和部署；已选前端启动路径时可省 |
| 10 | 枚举 docs、views、stores | 没有新增行为依据 |
| 11–12 | 总览、产品和后端文档 | 补背景，不能代替新的实现证据 |
| 13–14 | 枚举前端文档及路由目录、读 App.vue 和前端架构文档 | App.vue 对根组件细节有用；入门概览已有 mount 路径 |
| 15–16 | 搜 API 与 Agent，读 agent.py、再搜 Agent | 换成更深的第二条路径。原问题没有要求这条路径 |

第 9–16 轮共 16 次工具调用。若要讲跨层 HTTP 请求，应集中查代理配置或路由注册；第 8 轮只证明了代表性的前端路径。

## 实现和对照口径

在 PiChatAgent 的本地源码概览流程中，收到带正文的非说明文档后，后续模型请求进入证据核对阶段。由模型结合原问题判断关键职责是否仍有证据缺口，允许继续定点读取。运行时不按文件数决定证据是否充足。最后一个可用模型回合，若目录中全是工作区只读工具且已读到正文，则留给自然语言交付。含提交产物等工具的流程沿用原有工具权限。每次任务独立重置状态。

原题、仓库快照、工具集、温度和 16 轮上限沿用此前真实模型基线；new 是上轮保留的实际结果，coverage 是本轮工作区最终实现。AGICTO deepseek-flash 串行运行，每题每版一条样本。未命中和命中率取供应商输入计数，全部 token 为累计输入加输出。金额为账户余额前后差，精度到分。两组的缓存状态、运行时刻没有配平。检查回答正文和回执，不按 final 标识给通过。

## 回答依据与局限

- Gugu-web 第 7 轮命中实际运行函数，第 8 轮作答。前后端分工引用项目文档，代表路径用 preparation.py L299–338 和 execution.py L91–130 分别解释准备会话和消费事件。两段支持各自行为，它们的衔接还参考了项目架构文档。
- Atlas 读了 base.py、loop.py 和 retry.py，分别支撑注册约束、重试与耗尽、抖动等待。表格项目按 README 与 main.py 全文区分计划和实际导入。
- pi-agent 实现题读到初始化与访问器函数体；正确区分赋值复制与 getter 返回内部数组。循环内轮末 L259，内层结束后 L263，退出 L271 均有行号回执。架构题以根 README 描述包职责，以包清单和实际 import 说明已核实的依赖。实现题多用了两次工作区工具，未命中输入增加 4,650。
- 最终五份回答中，自动可解析的 75 处“文件名+行号”引用均落在已交给模型的正文或搜索片段内。单独行号和结论含义另做上述重点核对，没有逐句覆盖所有陈述。
- 最终版五题均自然结束（最多 13 轮）。五题模型发起的所有工具调用从 110 减到 85，含工具发现及未进入业务适配器的尝试。历史基线只计作对照。此次三个实验版本的账户余额减少分别为 ¥0.12、¥0.10、¥0.16，合计 ¥0.38。首个候选 Gugu-web 输出调用标记，Atlas 中断；第二个候选虽五题输出文本，但实现题漏核实状态初始化，因此未选用。上表展示最终工作区版本的全部结果。样本单次，架构题各次可能选择不同代表路径。
