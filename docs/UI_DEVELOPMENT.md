# UI 开发规范

适用于 tebb / desk-companion 的 React 工作台、桌宠聊天和新增界面。2026-11-06 用户确认，首批关联 [#285](https://github.com/lkun-lea/tebb/issues/285)。本规范是当前要求，历史截图和旧功能文档不得覆盖这里的参数。

## 优先级与职责

用户明确要求优先于外部 skill。桌面参考 [desktop-agent-ui](https://github.com/Ludi-Herry/desktop-agent-ui/blob/main/SKILL.md)，业务页面参考 [B 端规范](https://github.com/Ludi-Herry/b-end-design-system-skill/blob/main/SKILL.md)，实际移动/触控入口参考 [移动端规范](https://github.com/Ludi-Herry/mobile-design-system-skill/blob/main/SKILL.md)。本项目默认去边框，不因 skill 推荐微边框恢复整页描边；暗色字重固定减 40，不采用外部规范的减 100。

复用 React、reend-components、Lucide、Framer Motion、dnd-kit 与 FullCalendar，不引入第二套 UI 库。`client/src/client/ui-foundations.css` 唯一拥有语义 token、基础排版和字段外观；`ui-controls.tsx/css` 拥有公共控件及状态；页面拥有布局和业务状态。`--wb-*`、`--cp-*` 只引用语义 token，不建立独立色板。控件不发业务请求、不自行判定任务成功。

## 个人助理页面的布局与文案

参考 [Today 官网的交互演示](https://todayai.cn/)。其宽屏演示在切换任务、记忆和能力时保留左侧聊天，窄屏用带文字的底部图标呈现主要目的地。tebb 采用以下规则：

- **保留操作现场。** 宽屏把列表与详情组织成相邻层级；打开工具详情、关闭弹窗或返回聊天时保留查询、草稿和当前位置。窄屏改为单列，露出返回入口。固定导航只容纳常用目的地。
- **先说用户能做什么。** 条目首行用中文动作和对象，例如「回顾仓库近况」；次行写可得到的结果、范围或输出位置，例如「查看近 14 天的提交、合并请求和议题」。技术标识、参数、版本及模型调用指令放在详情。
- **用图形帮助识别。** 同类动作使用一致的线性图标，搭配文字。分组由小标题、留白、连续列表承载；状态通过可读文字表达。页面主操作最多突出一个，其余操作放在工具栏或详情。
- **让动作与实际影响一致。** 本机工具、云端浏览和调用记录各有入口。「浏览云端工具」由点击发起网络请求，「添加」只处理选中项。「从目录移除」可恢复，「停用本机调用」影响执行。交给 tebb 的任务显示提交回执，并提供回原会话的入口。
- **跨端验收。** 宽、窄视口都检查长名称换行、图标与标签对齐、键盘焦点、触控目标以及深浅主题。用打开、查找、修改、返回这一条实际路径验收，截图注明平台、页面与数据来源。

### 今日手记的背景与按钮

桌面双栏、独立阅读页和 Android 单栏共用阅读器。页面由上至下从天蓝过渡到浅灰和暖杏色，正文使用深墨色，半透明卡片让背景透出。长列表的内容区域保持可滚动。实际稿件与验收场景见 [#335](https://github.com/lkun-lea/tebb/issues/335)。

手记按钮由 `client/src/journal/buttons.js` 创建，外观由同目录的 `buttons.css` 定义。提交答复用蓝底主按钮，查看上下文用浅灰辅助按钮。时长选项使用白底、蓝点，选中后显示勾和描边，读屏同步读取按下状态。所有按钮保留至少 44 像素的点击高度、可见键盘焦点和减少动效设置。选中时长仅更新草稿，点击「回复原任务」才提交。

工具目录验收可在仓库根目录运行 `python -m unittest tests.test_http_api.HttpApiTests.test_tool_library_preview_and_local_policy tests.test_workflow_authoring`。界面从「设置 → 工具」进入。核对打开本机目录时无云端请求、云端预览后本地条目数不变、只添加选中项、改名后仍能按技术名搜索，以及停用后调用在适配器执行前终止。自定义能力的创建或修改以服务返回的定义版本为准；「交给 tebb」先返回任务回执。

## 十条铁律

| # | 强制要求 | 实现与验收 |
| --- | --- | --- |
| 1 | 默认去边框，靠约 1%–3% 微明度差分层，禁纯黑 #000 / #000000 | 浅色采用冷灰基底与白色表面，暗色采用分层深灰，具体色值统一读取 ui-foundations.css。指定基底与表面的色差按色板本身执行，hover 再做微变化。普通卡片禁用嵌套描边和左彩条。 |
| 2 | 输入框聚焦不加 outline，加深双环 box-shadow | 内环 1px、外环 3px，深浅主题均清晰；错误字段采用危险语义双环。鼠标和键盘聚焦均可辨，不丢失 label、帮助、错误和焦点语义。 |
| 3 | 暗色字重全量减 40 | 400→360、500→460、600→560。CSS 使用 --ui-weight-*，Tailwind 使用对应字重 token，禁止新增裸字重。系统静态字库可能映射到邻近字重；连续视觉效果须用支持细分字重的字库实测，不能仅凭 computed style 声称字体精确呈现。 |
| 4 | 流式新增文字逐字从 blur(6px) 到清晰 | 单字 90ms，cubic-bezier(.215,.61,.355,1)，相邻字错开 30ms。按 Unicode 字素处理组合字符；仅动画实际新到文本，不重播前缀，不伪造进度。代码与图表保持可读布局，长批次不可无限积压动画队列。 |
| 5 | 行内图标 vertical-align:-0.125em | 使用 .ui-inline-icon，仅用于文本行内 SVG；flex/grid 图标保留容器对齐，不对所有 SVG 全局偏移。图标按钮提供可读名称。 |
| 6 | 数字 tabular-nums | 正文全局继承等宽数字，耗时、token、调用数、金额、表格核验实际计算样式。覆盖字体时不能丢失此规则。 |
| 7 | 折叠使用 Grid 0fr→1fr | 内层 min-height:0、overflow:hidden，不用 JS 测量高度。关闭态防止隐藏控件被聚焦，aria-expanded 同步。输入框自适应并非折叠，沿用其高度逻辑。 |
| 8 | 正文 text-wrap:pretty | 标题可用 balance，代码与终端保留原始换行。不用裁掉正文、缩小字号实现防孤字。 |
| 9 | 拖拽过阻尼、确认反馈欠阻尼 | Spring：拖拽归位/吸附 stiffness:1200,damping:80,mass:1，零回弹；点赞/对勾 stiffness:380,damping:18,mass:1，微弹。跟手阶段不叠加落点动画，不争抢拖拽库的 transform。 |
| 10 | 复制成功对勾 2.5s 后淡出恢复 | 真正写入剪贴板后出现，连续复制重置期限，卸载清理计时器。失败、冲突、权限问题、结果未确认等业务状态不自动消退。 |

## 基础样式与共享控件

- 继续使用 hsl(var(--token) / alpha)。指定 HEX 在基础 token 转为 HSL 通道，禁止把 HEX 填入 HSL 通道变量，禁止页面重复定义主题。
- 默认控件低反差表面、无描边，按钮 hover 使用 3% 前景混色。一个操作区域最多一个主按钮；危险操作保留明确文字、确认与真实回执。
- 标准字号 12 / 14 / 16px，页面主标题可有独立大标题档；同页控制 3–4 档，最小 12px。历史页面未迁移的小字号不算已修复。
- 按钮覆盖默认、主要、危险、按下、禁用、忙碌与 focus-visible。busy 保留可读文字、原生 disabled 和 aria-busy，不自行增加重试。
- 字段 label/help/error 与既有 aria-describedby 保持关联；修正错误不替换输入节点或清空内容。checkbox、radio、range、文件与颜色选择器保留专属呈现。
- 反馈分 loading、empty、no_results、success、error、conflict、unconfirmed；后三种为 alert，其余为 status。文字传达状态，不只依赖颜色。持久状态不套用复制自熄。
- 圆角与阴影服务于层级，嵌套圆角按 R内=max(0,R外-padding) 校准，不增加装饰性发光或大阴影。
- prefers-reduced-motion:reduce 与 [data-reduce-motion=true] 均关闭新增过渡。forced-colors 使用系统色、实体边框和 Highlight outline；系统高对比是边框/outline 的必要例外。
- 保留真实任务状态、未保存保护、焦点返回、停止与核对、输入法和独立滚动契约，装饰调整不能改变业务状态机。

## 全端操作回执与 Toast

设置、工作台、侧边终端和桌宠聊天统一使用窗口内 Toast 承载一次性操作回执。保存配置、复制命令、更新密钥、导出完成等，以实际操作结果触发。迁移已有底部提示时按消息含义逐条审查；同一回执只展示一次。

| 消息 | 呈现与寿命 |
| --- | --- |
| 已完成的操作 | 在发起操作的窗口底部居中浮现，距安全边缘 16–24px，避开输入法和主操作。使用状态图标和简短动词，例如“模型配置已保存”。建议约 2.6 秒关闭，相同操作的重复回执更新当前消息并重新计时。 |
| 操作失败、冲突、结果未知 | 浮层提供即时反馈，需处理的原因和恢复入口在对应字段或任务详情保留到解决；需用户操作的提示支持手动关闭。 |
| 进行中的动作、持续状态、诊断证据 | 按钮显示忙碌，连接状态放在服务名旁，退出码、错误阶段和工具回执留在记录内。后台轮询刷新同一状态时保持安静。 |

同一窗口集中管理提示，区分重复和独立操作，独立回执按次序展示。浮层不参与页面排版、不抢键盘焦点。普通回执使用 polite 的 status，紧急且需要立即处理的错误使用 alert，同一消息只播报一次。减少动态效果时直接显示与关闭。验收覆盖重复保存、并发操作、失败未处理、窄窗及关闭窗口后清理计时器。

画像维度气泡使用每项独立的动画。指针悬停或键盘焦点只暂停对应气泡，离开后从原相位继续。整组暂停由明确的暂停控件或减少动态效果偏好控制。

## 工作台的视觉层级与产品识别

tebb 是常驻桌面的个人助手。设置要让人认出正在管理的对象，监控要让人找到失败的那一步，桌宠要让人看懂它正在做什么。评审先选一项真实任务，再决定这一屏最醒目的内容。以下是 tebb 对开源设计模式的取舍，尺寸为本项目设计起点。

### 参考与采用范围

| 参考 | tebb 的采用方式 |
| --- | --- |
| Microsoft Fluent 2 用间距表达亲疏，提供 4px 基准的间距阶梯。[布局](https://fluent2.microsoft.design/layout) | 作为间距参考。图标和短状态相距 4–8px，相关操作相距 8px，字段到操作 16px，独立分区 24–32px。先用间距分组，只在连续数据行或面板边界使用细线。 |
| GitHub Primer 的主从布局把选择对象与查看详情分开，并为窄窗提供独立导航入口。[导航模式](https://primer.style/product/ui-patterns/navigation/) · [React 源码](https://github.com/primer/react) | 用于服务目录、工具目录和运行列表。列表回答“选哪个”，详情回答“这个对象怎么了”。窄窗切为单栏并保留返回位置，键盘返回时恢复到所选项。 |
| IBM Carbon 区分结构化内容的骨架、局部操作的加载指示与渐进加载。[加载模式](https://carbondesignsystem.com/patterns/loading-pattern/) | 首次读取任务列表时按行占位，重新检查账号时只更新检查按钮及时间。桌宠形象预留原尺寸，已有会话内容在刷新时继续可读。 |
| VS Code 设置编辑器把同类设置分组，把重置等针对单项的操作放在就近菜单。[设置界面实例](https://code.visualstudio.com/docs/configure/settings) | 账号管理紧邻对应服务。断开账号、清除登录态在菜单内写明操作对象，触发时显示确认，结果回到原行。 |

### 如何把层级画出来

- **服务详情**。冷灰页面承托一个明度稍高的详情面。页首先放 40–48px 的服务图标与标题，状态紧跟名称，账号作为识别信息。操作靠近这个组合。选中项以低饱和主色底和更强字重表示；品牌色留给服务图标，成功绿与错误红专用于运行状态。飞书和 GitHub 共享版式，各自保留可辨认的图标。
- **排版与密度**。页标题复用 22–30px 标题 token，分组标题 16px，正文 14px，时间与次要信息 12px。同行账号、模型名与时间使用共同基线。长中文说明进入可换行的独立区域。把整页转成灰度时，仍应能凭字号、位置和间距找到对象、状态、下一步。
- **动作与颜色**。交互蓝用于当前最值得执行的动作。GitHub 未连接时突出“连接 GitHub”；已连接时可以只用次按钮“检查连接”，让服务名称保持视觉重心。配置失败时由失败原因和恢复操作占这个位置。低风险浏览页可以没有主按钮。
- **监控与工具评估**。运行详情的视觉重心是失败步骤及其回执。总耗时、工具调用数、失败数用等宽数字对齐，成功与失败同时用文字或形状区分。按时间排步骤，相邻重复调用默认聚合并可展开逐条回执。成功率旁标明范围和样本量；无调用显示“暂无调用”。
- **个性与动效**。桌宠形象用于桌宠启动、对话和首次体验；系统设置采用统一线形图标。一次状态变化只让一个区域动：按钮反馈就让按钮动，内容到齐就让占位原位淡出。普通过渡优先复用现有 120ms 时长，减少动态效果时直接切换，同时保留文字状态。

### 设计评审样例

用同一服务出三张样例：已连接、授权失效、600px 窄窗。已连接时能立即辨认账号，失效时能从原因直接找到恢复动作，窄窗和键盘操作都能回到原服务。工具页另取一次真实失败与一次零调用作为样例。预览标明模拟数据，核对深浅主题、减少动态效果和异步更新时的布局稳定性后，再记录实现验收结果。

### 飞书桌面参考：导航、列表、内容

用户提供的飞书消息页截图作为桌面构图的优先参考。图中浅蓝灰窗口衬底围合两块连续的浅色表面，左侧导航用白色选中底，中栏用头像、标题、摘要和时间形成扫读节奏，右侧空态只占很小一块。2026-11-21 确认采用冷灰外壳、白色内容面与交互蓝。

| 设计决定 | tebb 落地与评审要点 |
| --- | --- |
| 分栏承担不同任务 | 设置导航切换功能，服务或运行列表选择对象，详情承接操作。普通单表单页省去对象栏。分栏之间试用 8px 间隙，外层面板采用 10–12px 圆角。窄窗保留分类栏，列表与详情按可用宽度重排。 |
| 列表靠行结构形成秩序 | 图标固定同一列；标题与一行摘要左对齐；必要的时间或计数靠右。服务图标可有各自色彩，普通导航图标使用中性色。导航选中用明亮底色，对象选中使用浅蓝底并提供选中语义。长名称允许截断，进入详情可读全名。 |
| 主色有明确用途 | 主窗口使用低饱和蓝灰作为窗口衬底，内容保持近白。交互蓝用于焦点、选择与当前动作；授权失效继续用警示色和文字。时间、类别、状态只在影响判断时显示。深色主题按对应表面和语义色重新配对。 |
| 空白保持上下文 | 对话未选择时显示小尺寸 tebb 形象与一句操作提示；外部连接每行已有明确入口，空态无需重复列出服务。已选择对象后在同一内容面显示详情，加载时保持标题和布局稳定。 |
| 根据页面选择密度 | 对话列表的第二行用于消息摘要，工具列表的第二行用于调用情况，运行列表优先放失败步骤。详情里用短段落和固定字段列，对象页保留一个当前动作。图标、头像、色块不重复出现在每个小节。 |

### 设置窗口：分类导航与连续表单

设置页以用户提供的飞书设置截图为直接参考。窗口标题横跨分类栏和正文。分类栏使用浅灰底、统一线形图标与整行选中态。右侧是一块独立滚动的连续表面，标题、身份信息、字段、帮助和操作沿同一左边线排布。与上一节的对象浏览页分别选用布局。

- 从主窗口进入设置时，在原窗口正文区切换视图，以设置分类替换全局侧栏，保留原会话和草稿。设置分类常驻正文左侧，返回工作台时恢复先前位置。外部连接的少量服务在正文顶部切换，给账号和权限留出宽度；运行或工具检查需要浏览大量实例时再使用对象列表。
- 主要分组用标题、24–32px 间距和单条细线分隔。普通选项直接排在白色内容面，帮助紧贴对应字段；主题外观、会话密度等确实需要看差异的选项才用并排小样和单选控件。配置项保留自然宽度，宽屏余量留在右侧。
- 主按钮按文字宽度排在对应设置下方。选中、聚焦与主操作复用同一交互色系。屏幕缩窄时服务选项可换行，设置分类保留左侧入口。以示例账号评审普通态、过期态和长标签。

### 工作台右侧终端

终端从主工作区右侧展开。宽窗与正文并排，窄窗在正文右侧覆盖显示。支持放大、还原与收起，收起后由窗口顶部的终端入口重新打开，保留会话、草稿与输出。标题、会话选择和面板操作共用一行；命令、输出、退出回执和下一行提示符共享一个滚动区。状态色只标注有意义的输出，保留原始可复制文本。提示符展示实际 shell 和工作目录。启动命令走沙箱现有执行契约；运行中的输入、停止与最终回执对应同一个任务。示例回放标明模拟状态。

## 设置页与桌宠反馈

- 服务详情采用同一阅读顺序：服务名与状态、适用字段、当前操作、高级设置、活动记录。复用两列字段布局。视频平台与搜索配置嵌入详情时共用页面表面，隐藏重复的平台标题。已保存登录态与平台验证成功分别表述。
- 首屏只保留当前状态、下一步和会影响选择的提示。使用说明和诊断按需展开。费用、凭证去向、清除登录态等重要后果紧邻触发操作；失败原因与恢复入口保持可见。
- 同一操作组使用统一间距，行距和列距至少 8px，字段与操作组间距建议 16px。每组最多一个主按钮。低频账户管理收入更多菜单，危险操作明确命名并二次确认。
- 设置引导嵌入所属子页，只在当前步骤的目标可见时显示。取消指向手势与定位按钮。用户离开时收起引导；选择“稍后继续”时持久保存暂停意图与步骤，重开设置或应用后由用户主动恢复。
- 折叠配置只改变自身内容区。活动入口占据固定位置，记录状态变化和显式操作回执；初次读取只更新当前状态。后台刷新不得抢焦点或自动展开记录。
- 并排筛选项的控件顶边对齐，长标签或限定条件独立布局。窄窗口按整组换行，保留完整选项和可访问名称。
- 桌宠加载在原位置预留尺寸。短等待避免闪烁；较长等待显示轻量循环提示，并保留可读状态。内容就绪时短暂淡入。减少动态效果时使用静态状态。错误原因与重试入口持续可见，进度只使用真实数据。
- 验收覆盖浅色、深色、窄窗口、减少动态效果、键盘操作，以及暂停引导后重开设置、展开机器人配置时收到刷新结果。

个人资料首屏保留新增入口，刷新与同步归入资料管理菜单。来源设备和版本编号随条目管理按需查看。个人画像用四个可独立聚焦的维度气泡。悬停和键盘聚焦只暂停对应气泡，减少动态效果时全部静止。选择维度显示资料和补充入口。

覆盖矩阵使用单表头和等宽数字，点击行或用键盘激活能力名称可看样本明细。零记录与失败分别表达。

### 设置页实景验收

- 从工作台进入设置，核对单侧导航、返回位置、标题与正文左边线。在宽窗、窄窗和侧边工作区展开后分别检查内容实际可用宽度。
- 平台入口使用随客户端打包的官方品牌资源。无品牌的类别可直接显示名称。检查最终构建中的图片可解码。
- 展开菜单、详情、异常回执和长列表。检查相邻行的悬停与选中态、键盘焦点、字段换行和横向溢出。主视图显示业务名称、状态与时间，完整编号与模型指令放入详情。
- 以未连接、检查中、无资料、有失败及大量记录分别验收。初次读取连接状态只更新当前状态。空态提供一个可执行的恢复入口。
- 记录受检入口、窗口尺寸、状态和截图。渲染测试、构建成功和导航冒烟分别记录，视觉验收以实际渲染为准。

### 设置和监控页面的交互验收

| 场景 | 设计与验收 |
| --- | --- |
| 页面定位 | 内容容器在可用主区域水平居中。区内标题、字段和列表左对齐。侧栏返回入口靠左，使用方向图标、文字和可见焦点。 |
| 操作反馈 | 点击查看详情失败时以 toast 给出原因。连续轮询同一错误只提示一次。已有数据继续可读。 |
| 时间线与最近运行 | 深浅主题分别检查有事件、无阶段事件、只有完成事件的任务。标题优先显示实际请求。缺失时显示类型、时间与缺失状态，编号留给详情。长标题可换行。切换运行时保留列表、焦点和滚动位置，仅在详情区显示首次加载状态。回访先显示该运行的快照，连续切换时旧响应不能覆盖当前选择。 |
| 表格与图 | 可查看详情的表格行在有标题的独立对话框展示内容。关闭或 Esc 返回原焦点。大型依赖图提供放大、缩放和适配窗口。 |
| 数据摘要 | 首屏突出任务、模型和工具调用量。费用、统计口径和采样限制可展开。表后章节预留 24px，说明与对应操作保持相邻。 |
| 用例与渠道设置 | 长用例集展示目标和分类，可搜索、多选和检查版本。渠道设置复用主题色、表单与反馈样式。用长标题、旧记录、缺失数据和窄窗口验收。 |

运行监控的运行记录、协作任务、渠道任务与执行设置属于同级工作区。视图导航固定在内容上方，展开长时间线时仍可切换。折叠控件用于当前任务的次要字段、原始回执和说明。

运行监控与调试页面使用设置正文的滚动区域。长列表按批展开，瀑布图与刻度共用列宽。模型调用列表占用正文宽度，详情在弹窗中查看，关闭后保留筛选条件与已展示记录。评测批次的常规入口统一在设置「调试与评测」，外部 Agent 接口放在该页页头。

渠道任务与协作任务以可换行的任务摘要展示，点击打开独立详情。执行设置有独立入口。工具目录默认展示卡片，卡面显示工具名、集合和用途，参数、版本与调用诊断放入详情。工具目录展示已登记的定义；每次任务实际可发现的范围以当前授权为准。
