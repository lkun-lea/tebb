# tebb 业务弹窗

弹窗中出现选择项、可展开的资料行或详情入口时，按[控件用途与同级资料行](../../../docs/UI_DEVELOPMENT.md#控件用途与同级资料行)判断点击结果和字段层级，并按其中的键盘、缺项与窄窗场景验收。

先走真实入口，读负责读写的控制器和现有弹窗。列出对象、用户此刻要判断的事、当前状态允许的下一步，以及写入成功或失败后回到哪里。以仓库根目录的 `docs/UI_DEVELOPMENT.md` 和 `docs/UI_CONTRACT.md` 为准。

- 查看态突出对象名称、状态和已有内容。简单只读详情可以只有关闭入口。允许直接改变状态时把控件放在状态值旁。运行中优先查看进度，完成后优先查看结果，已归档只给仍有效的动作。让业务能力决定可用操作。
- 编辑态把可修改字段放在一起，让用户看得出保存的范围。草稿保留取消和未保存处理。确认态写清对象、动作与后果，以具体动词命名按钮。不可逆操作采用危险样式，初始焦点放在安全选项。
- 对可选空字段省略空值或合并为一句有意义的摘要，第一次添加的入口贴着所属内容。有值就显示内容及对应操作。区分无数据、尚在读取、读取失败和结果待核对，分别保留重试或核对路径。
- 较少使用的关联、归档及历史管理可折叠，入口用具体业务名称。后果提示贴近触发动作，关键风险在提交前可见。保留原权限、禁用、失败回执和返回位置。
- 从 WorkspaceDialog、公共表单控件、项目字体及语义色取样。早晚报可借鉴的是字段就地操作、玻璃面与亮蓝主按钮。根据内容密度选择布局；仅互斥视图才需要分段控件。检查玻璃面叠在实际列表、背景图和深浅底色上的正文、次要文字、焦点环、按钮文字对比；必要时提高面板不透明度。
- 从产品入口分别打开有内容和无内容的对象，试 Tab 顺序、Esc、关闭后的焦点与窄窗长文本换行，检查底部动作可滚动到达。逐项记录业务状态、操作结果及截图；运行时核对动效和减少动效设置。
